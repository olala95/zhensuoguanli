# F63 退药退款

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: M]

---

## 1. 职责

把 M07 已确认的**退药单**转换成退款：按退药明细（开方时价）计算退药金额，生成退款单并联动账单与支付。

---

## 2. 依赖

- 依赖：M07 F46（退药单与其明细，**只读**）、F61（退款流程）、F58（账单）
- 被依赖：M15 F119（退款冲减营收）

---

## 3. 涉及的表

`refund`、`refund_item`、`payment`、`bill`（M09 自有；`drug_return` 只读）

---

## 4. 规则

**R1 只消费已确认退药单。** M07 退药单状态必须是 `CONFIRMED`；未确认或已作废 → 拒绝（E3076）。

**R2 一张退药单最多一次退款。** 重复发起 → 拒绝（E3077），防止重复退钱；如需再退先走一般退款流程。

**R3 金额按开方时价。** 退药金额取退药明细记录的**开方时价 × 退回量**，M09 不重算药品价格（与 M07 F46 R7 同源，R-M09-1）。

**R4 映射到账单明细行。** 退药明细关联到处方明细 → 账单明细 `source_id`；找不到对应行（如处方未收费）→ 拒绝并提示（E3078）。

**R5 复用 F61 退款流程。** 本 F 是 F61 的**业务封装**：生成退款单、联动账单状态与支付状态、写高风险审计，规则完全一致。

**R6 同事务。** 退款单 + 明细 + 账单状态 + 支付状态 + 审计同一事务。

**R7 高风险审计与可追溯。** 退款记录保存 `drug_return_id`，可从退款反查退药单（反之亦然）。

**R8 幂等。** 同一退药单重复提交只生效一次（R-M09-12）。

---

## 5. 验收标准

**AC1（退药转退款）**
- Given M07 已确认退药单，退 1 盒（开方时价 1000 分）
- When 发起退药退款
- Then 生成 `RF` 单 1000 分，账单该行已退 1000
- 验证方式：自动

**AC2（未确认退药单被拒）**
- Given 退药单 DRAFT
- When 发起退款
- Then 拒绝 E3076
- 验证方式：自动

**AC3（重复退款被拒）**
- Given 该退药单已退过
- When 再次发起
- Then 拒绝 E3077
- 验证方式：自动

**AC4（金额按开方时价）**
- Given 开方时价 1000，现价 1200
- When 退药退款
- Then 退 1000 分
- 验证方式：自动

**AC5（可双向追溯）**
- Given 退款已生成
- When 按 `drug_return_id` 反查
- Then 命中原退药单；按退药单也能查到退款单号
- 验证方式：自动

**AC6（账单状态联动）**
- Given 退药后该账单所有金额退完
- When 完成退药退款
- Then 账单 `FULLY_REFUNDED`
- 验证方式：自动

**AC7（高风险审计）**
- Given 退药退款成功
- When 查 `audit_high_risk`
- Then 有记录含退药原因
- 验证方式：自动

**AC8（崩溃一致）**
- Given 退药退款事务中途强杀
- When 重启
- Then 退款单与账单状态一致，不出现重复退款
- 验证方式：自动

---

## 6. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E3076 | 退药单未确认/已作废 | 否 |
| E3077 | 该退药单已退款 | 否 |
| E3078 | 找不到对应账单明细（处方未收费） | 否 |
| E3074 | 退款金额超过可退净额 | 否 |

---

## 7. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 事务中断 | 整体回滚，可重新发起（幂等保证不重复） |
| 渠道退款失败 | 退款单标记 FAILED，允许重试 |
