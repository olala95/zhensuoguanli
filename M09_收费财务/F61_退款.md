# F61 退款

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: M]

---

## 1. 职责

对已收费账单的部分或全额退款：逐明细行指定退款数量/金额，生成退款单并按原支付渠道退回。

---

## 2. 依赖

- 依赖：F58/F59（账单与支付）、F60（明细）
- 被依赖：F63（退药退款复用本流程）、M15 F119（营收 = 收款 − 退款）

---

## 3. 涉及的表

`refund`、`refund_item`、`payment`、`bill`、`bill_status_log`

---

## 4. 规则

**R1 单号 `RF{yyyyMMdd}{4位}`**（契约 §1.2），状态 `DRAFT → SUCCEEDED | FAILED | VOID`。

**R2 必须指定明细行。** 退款逐行指定，金额 ≤ 该行**净额**（`amount_fen − 已退 − 已冲`），超额拒绝（E3074）。

**R3 账单状态联动（契约 §2.5）。** 全部退完 → `FULLY_REFUNDED`；部分退 → `PARTIAL_REFUNDED`；`PENDING` 账单不可退款（E3001）。

**R4 支付记录联动。** 对应 `payment` 转 `REFUNDED`；多笔支付时按**后付先退**顺序冲抵，保证不超退。

**R5 同事务。** 退款单 + 退款明细 + 账单状态 + 支付状态 + 状态日志同一事务；失败整体回滚。

**R6 高风险审计。** 退款必填原因，写 `audit_high_risk`（R-M09-10）。

**R7 幂等。** 同一 `idempotent_key` 不重复退款（R-M09-12）。

**R8 日结后仍可退，但走冲正语义。** 已日结账单的退款，除生成退款单外**同时生成负数明细行**（与 F62 一致的账面表达），保证日结后账表仍平衡。

**R9 退款不改原明细。** 只增 `refund_item` 与累计 `refunded_amount_fen`，原行金额不变（R-M09-3）。

---

## 5. 验收标准

**AC1（部分退款）**
- Given 账单 6525 分已付，退其中处置行 2000 分
- When 退款
- Then `RF` 单生成，账单 `PARTIAL_REFUNDED`，该行已退 2000
- 验证方式：自动

**AC2（全额退款）**
- Given 退完所有行
- When 退款
- Then 账单 `FULLY_REFUNDED`，支付记录 `REFUNDED`
- 验证方式：自动

**AC3（超额被拒）**
- Given 某行净额 1000
- When 退 1500
- Then 拒绝 E3074
- 验证方式：自动

**AC4（未收费不可退）**
- Given 账单 PENDING
- When 退款
- Then 拒绝 E3001
- 验证方式：自动

**AC5（原因必填）**
- Given 未填原因
- When 提交退款
- Then 拒绝 E2001
- 验证方式：自动

**AC6（原明细不变）**
- Given 退款完成
- When 查原 `bill_item`
- Then `amount_fen` 不变，仅 `refunded_amount_fen` 增加
- 验证方式：自动

**AC7（高风险审计）**
- Given 退款成功
- When 查 `audit_high_risk`
- Then 有记录含原因与明细
- 验证方式：自动

**AC8（幂等）**
- Given 同幂等键提交两次
- When 第二次
- Then 不产生第二笔退款
- 验证方式：自动

**AC9（崩溃一致）**
- Given 退款事务中途强杀
- When 重启
- Then 退款单与账单状态一致，不出现"已退钱账单未更新"
- 验证方式：自动

---

## 6. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E3074 | 退款金额超过可退净额 | 否 |
| E3001 | 账单状态不允许退款 | 否 |
| E2001 | 原因/明细缺失 | 否 |

---

## 7. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 渠道退款超时 | 标记 FAILED，允许重试（幂等键保证不重复退） |
| 事务中断 | 整体回滚，可重新发起 |
| 重复提交 | 幂等拦截 |
