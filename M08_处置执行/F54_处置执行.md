# F54 处置执行（开立）

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: M]

---

## 1. 职责

开立处置：选择项目或组套 → 生成执行记录（`SCHEDULED`）→ 供 M09 计费与后续执行。

---

## 2. 依赖

- 依赖：M02（Visit 必须处于 `IN_PROGRESS`）、F52（项目）、F53（组套）
- 被依赖：F55（执行）、M09 F58（账单）、M15 F120

---

## 3. 涉及的表

`treatment_execution`、`treatment_status_log`

---

## 4. 规则

**R1 必须挂就诊。** 无 `visit_id` 拒绝；Visit 处于 `COMPLETED` / `VOID` 拒绝开立（E3061）。

**R2 编号 `TE{yyyyMMdd}{4位}`**（契约 §1.2），事务内取号。

**R3 初始状态 SCHEDULED。** 开立即写状态日志（首次记录 `from_status=NULL`）。

**R4 价格与名称快照。** 开立时固化 `item_name_snap` / `price_fen` / `unit`（R-M08-4）。

**R5 数量与金额。** `quantity` ≥ 0.01；`amount_fen = round(price_fen × quantity)`（R-M08-5）。

**R6 患者快照。** 记录患者姓名/性别/年龄快照，不随患者主数据变更（与 M06 同族规则）。

**R7 组套展开。** 应用组套时逐项生成执行记录，共享一个 `package_id` 便于整体查看。

**R8 计费标记。** `charge_flag=0` 表示尚未进入账单；M09 生成账单时**只读不写**（R-M08-9）。

**R9 取消未执行处置。** `SCHEDULED` 可直接取消（填原因）；已进入 `IN_PROGRESS` 的走 F55 中断/取消。

---

## 5. 验收标准

**AC1（开立处置）**
- Given 就诊进行中，项目"静脉输液"2000 分 ×1
- When 开立
- Then 生成 `TE{yyyyMMdd}{4位}` 记录，状态 `SCHEDULED`，金额 2000 分
- 验证方式：自动

**AC2（就诊已完成不可开立）**
- Given Visit 已 COMPLETED
- When 开立
- Then 拒绝 E3061
- 验证方式：自动

**AC3（价格快照）**
- Given 开立后项目调价
- When 查执行记录
- Then 快照不变
- 验证方式：自动

**AC4（组套展开）**
- Given 应用 3 项组套
- When 开立
- Then 3 条记录，`package_id` 相同，可分别取消
- 验证方式：自动

**AC5（取消需原因）**
- Given 未填原因取消
- When 提交
- Then 拒绝 E2001
- 验证方式：自动

**AC6（金额精度）**
- Given 单价 333 分 × 3
- When 开立
- Then `amount_fen=999`
- 验证方式：自动

**AC7（审计留痕）**
- Given 开立与取消
- When 查 `audit_operation` 与 `treatment_status_log`
- Then 均有记录，取消另有 `audit_high_risk`
- 验证方式：自动

## 6. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E3061 | 就诊状态不允许开立处置 | 否 |
| E3060 | 项目已停用 | 否 |
| E2001 | 数量/原因缺失 | 否 |

|---|---|
