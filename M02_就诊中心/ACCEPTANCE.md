# M02 就诊中心 — 模块验收

## 1. 端到端场景

### S1 完整就诊生命周期（F05 → F06 → F07 → F08 → F09 → F07.4）
1. 患者 P 建档后创建 Visit（普通门诊，医生 A）→ 入队
2. 队列中看到 P，医生点击接诊 → IN_PROGRESS
3. 工作台拉起，写病历、开处方（由 M03/M06 完成）
4. 中途患者去采样 → 挂单（原因：检验采样）
5. 医生接诊下一位
6. 患者回来 → 恢复 → 继续
7. 点击完成就诊 → 前置检查通过 → COMPLETED

**通过标准**：状态流转全部合法；挂单恢复后上下文完整；完成前检查生效；全程审计完整。

### S2 退号场景（F125）
1. 创建 Visit → 患者未到
2. 作废，填原因
3. 检查：移出队列、不计入门诊量、审计完整

**通过标准**：作废后不可恢复；统计口径正确（不计入）。

### S3 已收费就诊的作废拦截（F125 → M09）
1. 创建 Visit → 开处方 → 收费
2. 尝试作废 → 被拒绝（存在有效收款）
3. 走 M09 退款
4. 再次作废 → 成功

**通过标准**：拦截生效且给出明确引导；退款后可作废。

## 2. 故障场景（本模块专属）

### FA1 接诊中崩溃
- 操作：医生接诊写病历过程中强杀进程
- 期望：Visit 状态保持 IN_PROGRESS；未保存草稿由 M03 草稿机制保护；重启后可继续
- 通过标准：状态不错乱，草稿可恢复

### FA2 挂单/恢复中途崩溃
- 操作：挂单或恢复操作执行中强杀
- 期望：状态明确为挂单前或挂单后，无中间态；挂单时长记录完整
- 通过标准：无半状态

### FA3 并发重复创建
- 操作：快速重复提交创建 Visit
- 期望：就诊号不重复；同患者重复创建有提示
- 通过标准：编号唯一性成立

### FA4 作废过程中单据作废失败
- 操作：注入某模块单据作废失败
- 期望：Visit 作废整体回滚，保持原状态
- 通过标准：不出现"Visit 已作废但处方仍有效"的不一致

### FA5 时间异常下的队列与等待时长
- 操作：系统时间回拨后查看队列
- 期望：等待时长不显示负值，标记时间异常
- 通过标准：无负数、无异常崩溃

## 3. 跨模块契约检查

| 检查项 | 期望 |
|---|---|
| 聚合根 | 无脱离 Visit 的临床单据 |
| 快照 | Visit 保存患者快照，不随患者主数据变更 |
| 改挂接口 | `patient.reassign()` 可用且被 F04 正确使用 |
| 状态机 | 全部状态变更走状态机，有状态日志 |
| 作废联动 | 未确认单据通过模块接口一并作废，无直接写表 |
| 统计口径 | VOID 不计入门诊量；is_first_visit 创建后不变 |
| 审计 | 创建/接诊/挂单/恢复/完成/作废全部有审计；作废有 `audit_high_risk` |
