# F08 留观 / 挂单

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: S]

---

## 1. 职责

将接诊中的 Visit 暂时挂起（如患者去缴费、去做外送检验采样、需要观察等待），保留上下文供后续恢复。

---

## 2. 依赖

- 依赖：F07（工作台触发）、F06（队列展示挂单标记）、F09（恢复）
- 被依赖：F09

---

## 3. 涉及的表

`visit`、`visit_status_log`、`visit_suspension`（M02 自有）

---

## 4. 规则

**R1 只能从接诊中挂单。** 仅 `IN_PROGRESS` 可挂单。`WAITING` 不需要挂单（本来就在等），`COMPLETED`/`VOID` 不可挂单。

**R2 挂单需填原因。** 原因从字典选择（缴费中 / 检验采样 / 等待报告 / 观察中 / 其他）+ 可选备注。原因必填。

**R3 挂单不阻塞医生。** 挂单后医生可立即接诊下一位；患者保留在队列中并标记"挂单"。

**R4 挂单期间数据保留。** 已写的病历草稿、已开的未确认处方全部保留，恢复后原样继续。

**R5 挂单期间禁止新增临床操作。** `SUSPENDED` 状态下不可新增处方/病历/检验（防止误挂到别的患者上下文）。如需新增必须先恢复（F09）。

**R6 挂单时长记录。** 记录挂单开始时间；恢复时计算挂单时长，写入 `visit_suspension` 供统计。

**R7 多次挂单允许。** 一次 Visit 可多次挂单与恢复，每次都记录（不是覆盖）。

**R8 挂单不收费、不改账单。** 挂单纯状态操作，不产生任何费用或单据。

**R9 挂单写审计。** 状态变更写 `audit_operation`；挂单原因进上下文。

---

## 5. 状态与流程

```
IN_PROGRESS → 点击挂单 → 选原因 → 置 SUSPENDED
  → 写 visit_suspension（原因、开始时间）
  → 写 visit_status_log + 审计
  → 队列中标记"挂单"，医生可接诊下一位
```

---

## 6. 验收标准

**AC1（基本挂单）**
- Given Visit 处于 IN_PROGRESS
- When 挂单并选择原因"检验采样"
- Then 状态置 SUSPENDED，`visit_suspension` 记录原因与开始时间，队列标记挂单，审计完整
- 验证方式：自动

**AC2（原因必填）**
- Given 挂单操作
- When 不填原因提交
- Then 拒绝，返回 `E2001`，状态不变
- 验证方式：自动

**AC3（数据保留）**
- Given 挂单前有 1 份病历草稿与 1 张未确认处方
- When 挂单后恢复（F09）
- Then 草稿与处方原样存在，可继续编辑
- 验证方式：自动

**AC4（挂单期间禁止新增）**
- Given Visit 处于 SUSPENDED
- When 尝试新增处方
- Then 拒绝并提示"请先恢复就诊"
- 验证方式：自动

**AC5（不阻塞医生）**
- Given Visit A 挂单
- When 医生从队列接诊 Visit B
- Then 正常接诊，A 仍在队列并标记挂单
- 验证方式：自动

**AC6（多次挂单）**
- Given Visit 挂单 → 恢复 → 再次挂单
- When 查看 `visit_suspension`
- Then 有 2 条独立记录，不是覆盖
- 验证方式：自动

**AC7（挂单时长）**
- Given 10:00 挂单，10:25 恢复
- When 查看记录
- Then 挂单时长 25 分钟
- 验证方式：自动（mock 时间）

**AC8（非法状态拒绝）**
- Given Visit 已 COMPLETED
- When 尝试挂单
- Then 拒绝，返回 `E3015`
- 验证方式：自动

---

## 7. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E2001 | 挂单原因必填 | 否 |
| E3015 | 当前状态不允许挂单 | 否 |
| E3013 | 状态已变更，请刷新 | 是 |

---

## 8. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 挂单写入中途崩溃 | 事务回滚；状态保持 IN_PROGRESS；重新挂单 |
| 状态已变（被他人改） | 提示刷新并以数据库为准 |
