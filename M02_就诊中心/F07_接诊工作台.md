# F07 接诊工作台

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: **L — 已拆分为 4 个子项**]

---

## 1. 职责

医生接诊的主操作界面：以一次 Visit 为中心，集成病历书写、处方开立、检验申请、处置开立、收费入口与患者历史。

**这是整个系统使用频率最高的界面**，也是跨模块集成度最高的地方。

## 5. 规则

**R1 单一 Visit 上下文。** 工作台一次只处理一个 Visit，切换 Visit 需明确操作（避免误操作到别的患者）。界面顶部始终显示当前患者姓名+就诊号。

**R2 患者身份醒目。** 顶部常驻显示：姓名、性别、年龄、就诊号、过敏史标签（来自 M03 F13）、初诊/复诊。**防止看错患者是本界面第一优先级。**

**R3 操作入口不重复实现。** 工作台**只提供入口与跳转**，不重复实现各模块的功能（如不自己画一个开方界面）。所有临床操作调用对应模块接口。

**R4 状态联动。** Visit 状态变化时工作台同步：
- `WAITING` → 显示"开始接诊"
- `IN_PROGRESS` → 显示全部临床操作
- `SUSPENDED` → 显示"恢复就诊"
- `COMPLETED` → 只读模式

**R5 未保存提示。** 切换到其他 Visit 或关闭工作台时，若存在未保存的临床内容（病历草稿、未确认处方），必须提示。

**R6 过敏史高危提醒。** 若患者有过敏记录（M03 F13），工作台顶部红色常驻展示，不依赖医生主动查看。

**R7 历史快速可达（F07.3）。** 至少展示最近 5 次就诊的日期、主诉/诊断、处方数；点击可展开详情。**只读，不可修改历史。**

**R8 完成就诊前置检查（F07.4）。** 尝试标记 `COMPLETED` 时：
- 未确认病历草稿 → 提示
- 未确认处方 → **强制提示**
- 未发药处方 → **强制提示**
- 未收费账单 → **强制提示**
可选择"强制完成"但必须填原因并写审计。

**R9 锁屏保护。** 锁屏（F100）时工作台冻结；解锁后恢复到锁屏前状态，未保存内容不丢。

## 6. 验收标准

### F07.1 框架

**AC1（患者身份醒目）**
- Given 接诊患者"张三"
- When 打开工作台
- Then 顶部常驻显示姓名、性别、年龄、就诊号、初/复诊；过敏史（若有）红色常驻
- 验证方式：自动

**AC2（单一上下文）**
- Given 工作台打开 Visit A
- When 尝试切换到 Visit B
- Then 需明确操作；切换后界面全部内容变为 B 的数据
- 验证方式：自动

**AC3（状态联动）**
- Given Visit 处于 WAITING
- When 打开工作台
- Then 显示"开始接诊"，临床操作不可点；点击后状态变 IN_PROGRESS 且操作解锁
- 验证方式：自动

### F07.2 操作入口

**AC4（拉起各模块）**
- Given 工作台打开
- When 点击"写病历""开处方""开检验""开处置"
- Then 分别拉起 M03 / M06 / M05 / M08 的功能，且自动带上当前 Visit 上下文
- 验证方式：自动（跨模块）

**AC5（不重复实现）**
- Given 检查代码
- When 审查工作台
- Then 无重复的开方/写病历逻辑，全部走模块接口
- 验证方式：自动（代码审查/调用审计）

**AC6（返回带回结果）**
- Given 从工作台开了一张处方
- When 返回工作台
- Then 工作台显示该处方（单号、状态、金额）
- 验证方式：自动

### F07.3 历史查看

**AC7（历史概览）**
- Given 患者有 5 次历史就诊
- When 查看历史
- Then 显示 5 次的日期、诊断、处方数；可展开详情；**只读**
- 验证方式：自动

### F07.4 完成就诊

**AC8（前置检查）**
- Given 存在一张未收费账单
- When 点击"完成就诊"
- Then 强制提示未收费，列出单号
- 验证方式：自动

**AC9（强制完成留痕）**
- Given 存在未收费账单
- When 选择"强制完成"并填原因
- Then 状态置 COMPLETED，`audit_operation` 含原因与未完成项清单
- 验证方式：自动

**AC10（完成后只读）**
- Given Visit 已 COMPLETED
- When 打开工作台
- Then 只读模式，**不可新增处方/病历**；如需补充只能走作废重开或新 Visit
- 验证方式：自动

**AC11（未保存提示）**
- Given 有未保存的病历草稿
- When 切换 Visit 或关闭工作台
- Then 提示保存/丢弃/取消
- 验证方式：自动

**AC12（锁屏保护）**
- Given 工作台有未保存内容
- When 触发锁屏并解锁
- Then 未保存内容仍在，恢复到锁屏前状态
- 验证方式：自动

## 7. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E3013 | Visit 状态已变更，请刷新 | 是 |
| E3014 | 存在未完成项（可强制） | 否 |
| E6001 | 未登录/已锁屏 | 否 |

---

## 8. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 工作台打开时 Visit 已被他人改状态 | 提示刷新并以数据库状态为准 |
| 某模块拉起失败 | 提示具体模块不可用，其余功能仍可用（不整体崩溃） |
| 崩溃 | 未保存草稿由各模块自身的草稿机制保护（M03/M06），工作台不持有业务数据 |

---

## 9. 契约缺口

- **需 M03/M05/M06/M08 提供"带 Visit 上下文拉起"的入口接口**，契约在第一阶段 M03 开发时冻结。
- 需 M03 提供过敏史查询接口（`allergy.list(patientId)`）供工作台顶部常驻展示。
