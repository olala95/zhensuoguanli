# F05 创建 Visit

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: M]

---

## 1. 职责

为已存在的患者创建一次就诊记录，分配就诊号，指定接诊医生与就诊类型，进入候诊队列。

---

## 2. 依赖

- 依赖：M01（患者存在性校验与快照）、M14（编号、用户上下文）、M12（审计）、F06（创建后入队）
- 被依赖：M03 / M05 / M06 / M08 / M09

---

## 3. 涉及的表

`visit`、`visit_status_log`、`visit_queue`（M02 自有）
只读 `patient`（M01，通过接口）

---

## 4. 规则

**R1 必须挂在已存在的患者下。** 无患者不允许建 Visit。建档与建 Visit 可一步完成（M01 F01 的"保存并开就诊"），但内部仍是两个步骤、一个事务边界内各自完整。

**R2 同时只有一个进行中 Visit（R-M02-4）。** 创建时检测该患者是否有 `WAITING`/`IN_PROGRESS`/`SUSPENDED` 的 Visit：
- 有 → 提示并展示该 Visit，引导复用
- 用户坚持新建 → 要求填原因，写 `audit_operation`（原因进上下文）

**R3 就诊类型可选。** 普通门诊 / 急诊 / 复诊 / 体检 / 其他（字典可配）。类型影响队列优先级（急诊优先）。

**R4 接诊医生必填。** 默认为当前登录的医生角色用户；可指定其他医生。后续可改（写审计）。

**R5 就诊号事务内取号。** `V{yyyyMMdd}{3位}`，每日重置。允许跳号不允许重号。

**R6 初诊/复诊自动判定。** 创建时查询该患者是否有历史 `COMPLETED` Visit：无 → `is_first_visit=1`。**该字段创建后不再变更**（即使后来发现判断有误），以保证 M15 统计口径稳定。

**R7 创建后自动入队。** 状态置 `WAITING` 并写入 `visit_queue`，队列序号按创建时间 + 急诊优先。

**R8 创建即写状态日志与审计。** `visit_status_log` 记录创建事件；`audit_operation` 记录 create。

**R9 患者快照固化。** Visit 保存患者姓名/性别/出生日期的当时快照，不随患者主数据变更。

**R10 创建 Visit 不收费。** 挂号费（若有）通过 M09 账单收取，不在本功能内产生费用。

---

## 5. 状态与流程

```
选择患者（新建或搜索已有）
  → 检测该患者是否有进行中 Visit
      → 有：提示复用 / 坚持新建（填原因）
  → 选择就诊类型、确认接诊医生
  → 判定初诊/复诊
  → 事务内：取就诊号 → 写 visit → 写状态日志 → 写入队 → 写审计
  → 返回就诊号，进入候诊
```

---

## 6. 验收标准

**AC1（基本创建）**
- Given 患者 P 无任何进行中 Visit
- When 创建 Visit（类型：普通门诊，医生：A）
- Then 生成就诊号 `V{今日}{3位}`，状态 WAITING，已入队，`visit_status_log` 有创建记录，审计完整
- 验证方式：自动

**AC2（重复创建拦截）**
- Given 患者 P 已有一个 WAITING 的 Visit
- When 再次创建
- Then 提示已有进行中就诊并展示就诊号；引导复用
- 验证方式：自动

**AC3（强制新建留痕）**
- Given 提示已有进行中 Visit
- When 用户选择"仍然新建"并填原因
- Then 创建新 Visit，`audit_operation` 上下文含原因
- 验证方式：自动

**AC4（急诊优先）**
- Given 队列中有 3 位普通患者
- When 创建一位急诊 Visit
- Then 该 Visit 排在队首
- 验证方式：自动

**AC5（就诊号唯一且按日重置）**
- Given 今日已创建 5 个 Visit
- When 再创建一个
- Then 就诊号为当日第 6 号；跨日后序号从 001 重新开始且全局不重复（含日期前缀）
- 验证方式：自动

**AC6（初复诊判定）**
- Given 患者首次就诊
- When 创建 Visit
- Then `is_first_visit=1`；第二次创建时为 0
- 验证方式：自动

**AC7（患者快照固化）**
- Given 创建 Visit 时患者姓名为"张三"
- When 之后患者改名为"张三丰"
- Then 该 Visit 中患者姓名快照仍为"张三"
- 验证方式：自动

**AC8（必填校验）**
- Given 未指定接诊医生
- When 提交
- Then 拒绝并提示，不消耗就诊号
- 验证方式：自动

**AC9（崩溃一致性）**
- Given 创建过程中强杀进程
- When 重启检查
- Then Visit 要么完整存在（含状态日志、队列、审计）要么完全不存在
- 验证方式：自动

**AC10（并发取号）**
- Given 快速连续创建 20 个 Visit
- When 检查就诊号
- Then 20 个号全部唯一无重复
- 验证方式：自动

---

## 7. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E2001 | 必填缺失（患者/医生） | 否 |
| E3007 | 患者已合并，不可建就诊 | 否 |
| E3012 | 患者已有进行中 Visit（可强制） | 否 |
| E1010 | 审计写入失败 | 是 |

---

## 8. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 创建中途崩溃 | 事务回滚；重新创建；就诊号允许跳号 |
| 入队失败 | 事务回滚（Visit 不创建） |
| M01 接口不可用 | 拒绝创建并提示（不允许创建无患者的 Visit） |
