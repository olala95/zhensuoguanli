# F94 完整性检查

[TYPE: JOB] [PRIORITY: P0] [SIZE: M]

---

## 1. 职责

定期与按需证明"**库是好的**"：SQLite 页结构完整性 + 外键完整性 + 业务不变量一致性。
核心能力已在第一阶段交付（`core/backup.py:integrity_check_now`、
`core/selftest.py:check_invariants`）；本文件冻结**检查项全集与失败处置**。

---

## 2. 依赖

- 依赖：`core/db`（PRAGMA）、所有业务模块（不变量跨表）
- 被依赖：F90（备份后校验）、F93（恢复后校验）、M14 F105（健康检查）、启动自检

---

## 3. 涉及的表

`integrity_check`、`sys_health_check`（M14 拥有，只读写入由其服务提供）

---

## 4. 规则

**R1 检查项三层，缺一层不算"库是好的"。**

| 层 | 手段 | 失败含义 |
|---|---|---|
| 页结构 | `PRAGMA integrity_check` | 文件物理损坏 |
| 引用完整 | `PRAGMA foreign_key_check` | 有孤儿行（通常是绕过服务接口写库） |
| 业务不变量 | `selftest.check_invariants()` | 跨表账实不符（库存负数、账单≠明细等） |

**R2 触发时机。** ① 每次备份完成后（对备份文件）；② 每次启动自检（对当前库）；
③ 恢复完成后；④ 手动（管理员）。

**R3 结果落表。** 每次检查写一条 `integrity_check`（check_type = DB / BACKUP_VERIFY /
POST_RESTORE），含耗时与明细 JSON。**结果只增不改不删**（03 §4.2）。

**R4 失败即只读。** 页结构损坏（integrity_check ≠ ok）**立即** `db.set_readonly(True)`
并写 `audit_high_risk`（R-M13-5：绝不在坏库上继续写）。

**R5 不变量违规不进只读，但必须告警。** 不变量违规通常是**业务 bug** 而非文件损坏，
进只读会让诊所停摆；处理方式：写 `audit_high_risk` + `crash_recovery_log`，
标记 `NEED_MANUAL_REVIEW`，在 UI 健康检查页显著提示（R-M13-6）。

**R6 检查本身不得改数据。** 只 SELECT 与 PRAGMA，禁止任何"顺手修复"。

**R7 可量化。** 返回 `{integrity_check, foreign_key_violations, invariants, ok, duration_ms}`，
便于在健康检查页展示与测试断言。

---

## 5. 验收标准

**AC1（三项全查）**
- Given 正常库
- When 执行完整性检查
- Then 返回含 integrity_check / foreign_key_violations / invariants 三项结果
- 验证方式：自动

**AC2（发现外键违规）**
- Given 人为插入一条孤儿行（绕过服务接口）
- When 执行检查
- Then foreign_key_violations 非空，ok=false
- 验证方式：自动

**AC3（发现不变量违规）**
- Given 人为把某 bill 的 total 改成与明细不符
- When 执行检查
- Then invariants 非空，且系统**未**进入只读
- 验证方式：自动

**AC4（页结构损坏进只读）**
- Given 模拟 integrity_check 返回非 ok
- When 执行检查
- Then `db.is_readonly()` 为 true，且存在高风险审计
- 验证方式：自动（用可注入的探测函数，不真破坏库文件）

**AC5（结果落表）**
- Given 一次检查
- When 查 `integrity_check`
- Then 新增一条记录，含 result 与 duration_ms
- 验证方式：自动

**AC6（检查不改数据）**
- Given 检查执行前后
- When 对比关键表的行数
- Then 完全一致
- 验证方式：自动

---

## 6. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E1003 | 页结构损坏 | 否（需恢复） |
| E1005 | 已进只读，业务被拒 | 是（恢复后） |

---

## 7. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 页结构损坏 | 进只读 → 提示管理员用 F93 从最近备份恢复 |
| 外键违规 | 定位违规行，由对应模块服务补写或清理（**禁止直接 DELETE**） |
| 不变量违规 | 人工核对账实，走对应业务的冲正/盘点流程，禁止直接改数 |

---

## 8. 契约缺口

- 不变量清单随业务模块增长而增长；**新增模块若引入新的"账实必须一致"关系，
  必须同步在 `selftest.check_invariants()` 中补一条**，否则该检查会静默失去意义。
