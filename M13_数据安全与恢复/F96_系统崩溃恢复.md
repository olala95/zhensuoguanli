# F96 系统崩溃恢复

[TYPE: SERVICE] [PRIORITY: P0] [SIZE: M]

---

## 1. 职责

进程被强杀 / 断电 / 蓝屏后**下一次启动时自愈**：SQLite WAL 会自动回滚未提交事务，
但"业务层面挂在中途的任务"不会自己收敛。本功能负责把这些半成品**标记到确定状态**。

> 核心检测（`core/selftest.detect_crash`）已在第一阶段交付；本文件补齐
> **任务收敛**（导入 / 打印 / AI / 发药 / 收费）与**只读降级**。

---

## 2. 依赖

- 依赖：`core/selftest`（WAL 残留 + 不变量）、M14 F128（导入任务）、M10（打印任务）、
  M04（AI 任务）、M07（发药）、M09（收费）
- 被依赖：启动流程（`core/runtime.bootstrap`）

---

## 3. 涉及的表

`crash_recovery_log`；**只读判定** `import_job`（M14）/ `print_job`（M10）/
`ai_task`（M04）/ `dispense`（M07）/ `bill`（M09）

---

## 4. 规则

**R1 数据由事务保证，任务由代码收敛。** SQLite WAL 保证**不会**出现半截的
库存扣减或半截账单；需要收敛的是"状态停在 RUNNING/PRINTING 但永远不会再推进"的任务。

**R2 启动即检测。** 启动时：
① 检查 `-wal` 残留（有残留 = 上次非正常退出）；
② 跑一遍不变量校验；
③ 扫描所有处于**进行中**状态的任务。

**R3 收敛规则（只做"拉回确定态"，不做业务补偿）。**

| 任务 | 卡住状态 | 收敛为 | 依据 |
|---|---|---|---|
| 导入 `import_job` | RUNNING | FAILED + 备注"崩溃中断" | R-M13-7 |
| 打印 `print_job` | PRINTING | FAILED（可重打） | 打印无资金影响 |
| AI `ai_task` | RUNNING | FAILED（未超重试则 RETRYING） | 幂等，可重跑 |
| 发药 `dispense` | 未完成的中间态 | **不自动处理**，标记人工复核 | 涉及库存 |
| 收费 `bill` | PENDING 且无 payment | **不自动处理**，标记人工复核 | 涉及资金 |

**R4 资金与库存相关的一律不自动补偿。** 发药与收费必须由人确认后再冲正/重做
（R-M13-7：看门狗只做拉起与收敛）。

**R5 收敛动作走对方模块的服务函数。** M13 **不直接 UPDATE** 别人的表；
通过 `m14_system.recover_stale_imports()` 等已有接口，或由对方模块暴露的
`recover_*` 函数（表所有权 R2）。

**R6 留痕。** 每个收敛动作写 `crash_recovery_log`（issue / action_taken / result），
并在有违规时写 `audit_high_risk`（CRASH_INCONSISTENT）。

**R7 严重不一致 → 安全模式。** 不变量违规非空时，启动报告 `safe_mode=true`，
UI 顶部红条提示"发现数据不一致，请核对或恢复备份"，**但不阻断登录**（医生可能
急需调阅历史病历）。

## 5. 验收标准

**AC1（WAL 残留被识别）**
- Given 上次崩溃留下非空 `-wal`
- When 本次启动
- Then 自检项 crash_recovery 报 WARN/FAIL，`crash_recovery_log` 有记录
- 验证方式：自动

**AC2（残留导入任务被收敛）**
- Given 一个 RUNNING 的 import_job
- When 启动崩溃恢复
- Then 该任务变为 FAILED，备注含"崩溃中断"
- 验证方式：自动

**AC3（残留打印任务被收敛）**
- Given 一个 PRINTING 的 print_job
- When 启动崩溃恢复
- Then 该任务变为 FAILED，且可重新打印
- 验证方式：自动

**AC4（残留 AI 任务被收敛）**
- Given 一个 RUNNING 的 ai_task（retry_count=0）
- When 启动崩溃恢复
- Then 变为 RETRYING（未超上限）；已超上限则 ABANDONED
- 验证方式：自动

**AC5（发药/收费不自动补偿）**
- Given 存在可疑的发药或收费中间态
- When 启动崩溃恢复
- Then 该记录**状态不变**，但在恢复报告中列为"需人工复核"
- 验证方式：自动

**AC6（干净启动不误报）**
- Given 正常退出的库（无 WAL 残留，无残留任务）
- When 启动
- Then crash_recovery 报 OK，不产生收敛动作
- 验证方式：自动

**AC7（不变量违规进安全模式）**
- Given 人为制造账实不符
- When 启动自检
- Then `safe_mode=true`，但登录仍可用
- 验证方式：自动

## 6. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E1006 | 进程异常退出遗留 | 否（已自动收敛） |
| E1003 | 严重损坏 | 否 |

---

## 7. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 收敛过程中写库失败 | 记日志 + 保留原状态，下次启动重试（收敛是幂等的） |
| 不变量违规无法自动修复 | 人工核对，必要时用 F93 回滚到最近备份 |

---

## 8. 契约缺口

- 崩溃恢复**依赖各模块暴露收敛接口**。目前只有 M14 有 `recover_stale_imports()`；
  M10 / M04 的收敛接口需随本功能补齐（放在各自模块内，M13 只做编排）。
