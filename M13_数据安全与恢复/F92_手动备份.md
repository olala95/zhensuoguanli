# F92 手动备份

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: S]

---

## 1. 职责

让管理员在**任何时刻**都能立刻做一次全量备份（比如大批量导入前、月度结账前、
拷到 U 盘前）。核心能力已在第一阶段交付（`POST /api/system/backup`）。

---

## 2. 依赖

- 依赖：F90（同一套备份实现）、M12（审计）、M14（权限 `system.backup`）
- 被依赖：F93（恢复源）、管理员日常运维

---

## 3. 涉及的表

`backup_job`、`backup_file`、`integrity_check`

---

## 4. 规则

**R1 管理员权限。** 权限点 `system.backup`；非管理员拒绝（E6002）。

**R2 不受"每日一次"限制。** 手动备份**永远执行**，即使当天已有 SUCCEEDED 全量
（F90 R2 的幂等只约束自动触发）。

**R3 必须带原因。** `reason` 缺省为 `MANUAL`，允许自定义备注（如"导入前"），
写入 `backup_job.reason` 便于事后追溯"这份备份当时是为了什么"。

**R4 同步返回文件信息。** 返回 `job_no / file / size / valid`，管理员可据此去目录里
拷贝文件；**UI 需显示校验结果**，INVALID 要显著提示。

**R5 与自动备份同流程。** checkpoint → `VACUUM INTO` → SHA256 → integrity_check →
登记 → 清理，不做任何简化（R-M13-2）。

**R6 失败必须显性。** 抛 E1004/E1002，不返回"成功但其实是 skipped"。

**R7 审计。** `audit_operation`（M13 / backup.manual）。

---

## 5. 验收标准

**AC1（手动备份成功）**
- Given 管理员已登录
- When 调用手动备份
- Then 生成新备份文件，`backup_job.reason` = 传入值或 MANUAL
- 验证方式：自动

**AC2（同一天可重复执行）**
- Given 当天已有成功备份
- When 再次手动备份
- Then 仍然执行，产生第二份文件
- 验证方式：自动

**AC3（非管理员被拒）**
- Given 医生账号
- When 调用手动备份
- Then 拒绝 E6002
- 验证方式：自动

**AC4（返回校验结果）**
- Given 手动备份完成
- When 查看返回
- Then 含 valid 字段；校验失败时 valid=false 且文件标记 INVALID
- 验证方式：自动

**AC5（列表可查）**
- Given 已有若干备份
- When 查询备份列表
- Then 按时间倒序返回，含 job_no / 类型 / 状态 / 大小 / 校验状态
- 验证方式：自动

**AC6（审计留痕）**
- Given 一次手动备份
- When 查 `audit_log`
- Then 存在 M13 / backup.manual 的操作审计
- 验证方式：自动

---

## 6. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E6002 | 非管理员 | 否 |
| E1002 | 磁盘空间不足 | 否 |
| E1004 | 备份 I/O 失败 | 是 |

---

## 7. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 目录不可写 | 检查 `backup.dir` 配置与目录权限后重试 |
| 磁盘满 | 清理旧备份 / 更换目录后重试 |
