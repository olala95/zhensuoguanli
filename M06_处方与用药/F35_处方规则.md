# F35 处方规则

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: **L — 已拆分为 4 个子项**]

> **本功能是本模块唯一的强制阻断关口。** 除过敏外全部为提醒，但过敏必须拦截。

---

## 1. 职责

对处方做规则校验：过敏、剂量、相互作用、重复用药、皮试要求、特殊人群。

---

## 2. 拆分

| 子项 | 内容 | 优先级 | 强度 |
|---|---|---|---|
| **F35.1** 过敏校验 | 患者过敏史 vs 处方药品 | P0 | **强制拦截** |
| **F35.2** 皮试前置校验 | 需皮试药品是否已做且阴性 | P0 | **强制拦截** |
| **F35.3** 剂量与频次校验 | 单次/日剂量上限、疗程 | P0 | 提醒 |
| **F35.4** 相互作用与重复用药 | 同类重复、已知相互作用 | P1 | 提醒 |

## 5. 规则

**R1 过敏强制拦截（F35.1）。** 处方药品命中患者过敏记录 → **强制拦截**，不可提交。医生显式说明理由（如"患者已确认耐受"）后可强制继续，但：
- 必须填写理由
- 写 `audit_high_risk`
- 界面红色高危警告

**R2 过敏匹配范围。** 匹配：同一通用名、同类药物（如青霉素类）、配置的交叉过敏关系。**宁可多报不可漏报。**

**R3 过敏数据不可用时的降级方向。** 若 M03 过敏接口失败 → **强制提示"过敏史未知"并要求人工确认**，**绝不视为"无过敏"**（安全方向降级）。

**R4 皮试强制前置（F35.2）。** 需皮试药品：`skin_test` 无记录或结果为阳性 → **不得进入 CONFIRMED**。

**R5 剂量提醒不阻断（F35.3）。** 超 `max_single_dose` / `max_daily_dose` → 提醒，医生确认后可继续，记录命中。

**R6 相互作用与重复用药提醒（F35.4）。** 同类药物重复、已知相互作用 → 提醒不阻断。规则表可配置维护。

**R7 规则命中全部记录。** 每次校验的命中项写入 `prescription_rule_hit`（含规则类型、强度、医生处置：接受/忽略/强制继续）。

**R8 校验在提交与确认时都跑。** 提交（PENDING）与确认（CONFIRMED）时各跑一次；确认时若处方已变更需重跑。

**R9 AI 建议不豁免。** 来自 M04 F24 的处方走**完全相同**的校验（R-M06-4）。

**R10 规则校验失败 = 拒绝提交。** 若校验服务本身异常（不是规则命中，而是跑不起来）→ **拒绝提交**，不允许无校验通过。

## 6. 验收标准

### F35.1 过敏

**AC1（过敏强制拦截）**【关键】
- Given 患者青霉素过敏，处方含阿莫西林
- When 提交
- Then **强制拦截**，提交失败，红色高危提示
- 验证方式：自动

**AC2（强制继续需理由+审计）**
- Given 过敏拦截
- When 医生填理由"患者已确认耐受"强制继续
- Then 允许继续，写 `audit_high_risk` 含理由
- 验证方式：自动

**AC3（同类药物匹配）**
- Given 患者青霉素类过敏，处方含青霉素类其他药
- When 提交
- Then 同样拦截
- 验证方式：自动

**AC4（过敏数据不可用的降级方向）**【关键】
- Given M03 过敏接口不可用
- When 提交处方
- Then **强制提示"过敏史未知"要求人工确认**，不得视为无过敏
- 验证方式：自动（mock 接口失败）

**AC5（AI 建议不豁免）**【关键】
- Given 过敏患者，AI 恰好建议了该过敏药，医生采纳
- When 提交
- Then **同样强制拦截**
- 验证方式：自动（跨模块，需 M04 配合）

### F35.2 皮试

**AC6（皮试未做拦截）**
- Given 药品需皮试且无皮试记录
- When 确认处方（F37）
- Then 拒绝确认，提示先做皮试
- 验证方式：自动（跨模块，需 F36 配合）

**AC7（皮试阳性拦截）**
- Given 皮试结果阳性
- When 确认处方
- Then 拒绝确认
- 验证方式：自动

### F35.3 剂量

**AC8（超量提醒不阻断）**
- Given 单次剂量超过药品资料上限
- When 提交
- Then 提醒，医生确认后可通过，记录命中
- 验证方式：自动

### F35.4 相互作用

**AC9（重复用药提醒）**
- Given 处方含两种同类药物
- When 提交
- Then 提醒重复用药，不阻断
- 验证方式：自动

### 通用

**AC10（命中记录完整）**
- Given 多次规则命中与处置
- When 查看 `prescription_rule_hit`
- Then 含规则类型、强度、医生处置、时间
- 验证方式：自动

**AC11（校验服务异常拒绝提交）**
- Given 规则校验服务异常（非命中）
- When 提交处方
- Then **拒绝提交**，不允许无校验通过
- 验证方式：自动（注入异常）

**AC12（确认时重跑）**
- Given 处方提交后修改了明细
- When 确认
- Then 重新校验，不允许用旧结果
- 验证方式：自动

## 7. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E3020 | 命中过敏原（强制） | 否（需强制继续） |
| E3035 | 皮试未做或阳性（强制） | 否 |
| E3036 | 剂量超限（提醒） | 是（确认后） |
| E3037 | 规则校验服务异常，拒绝提交 | 是 |
| E3021 | 过敏史未知，需人工确认 | 是 |

---

## 8. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 过敏接口失败 | 向"更谨慎"降级：强制人工确认（AC4） |
| 规则服务异常 | 拒绝提交（不静默放行），提示重试 |
| 崩溃 | 校验结果不半写；重新校验 |

---

## 9. 契约缺口

- 需 M03 明确过敏匹配规则（同通用名 / 同类 / 交叉过敏表）。交叉过敏关系表建议纳入 `sys_dict` 或独立配置。
