# F113 中药处方规则

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: M]

> 新增功能点。中药规则的强度分布与 F35 不同：**只有毒性饮片超量是强制二次确认，其余全部提醒**。
> 医生的处方权不能被程序硬拦，但必须留痕（契约 §8）。

---

## 1. 职责

对饮片 / 颗粒处方做专项规则校验：剂量上限、毒性饮片、配伍禁忌（十八反十九畏）、妊娠禁忌、
饮片必填项、重复药味、味数异常。

---

## 2. 依赖

- 依赖：**F110**（`herb.max_dose_g` / `is_toxic` / `pregnancy_flag`）、**F111**（每味剂量与脚注）、
  `herb_compatibility`（配伍禁忌表，M06 自有）、M03（`diagnosis` 证型，用于经验方匹配提示）、M14（配置）
- 被依赖：F111（提交与确认时）、F112（计价不影响规则）、M04 F24（AI 建议预检）

---

## 3. 涉及的表

`prescription_rule_hit`（M06 自有，与 F35 共用，靠 `rule_type` 区分）
`herb_compatibility`（M06 自有）
**只读** `herb`（M06）、`diagnosis`（M03）

---

## 4. 规则

**R1 强度分级固定。**

| 规则 | 强度 | 说明 |
|---|---|---|
| 重复药味（同一处方同一饮片出现两次） | **强制拦截** | 属数据错误，不是临床判断 |
| 毒性饮片超限量 | **强制二次确认** + `audit_high_risk` | 契约 §8 |
| 剂量超 `max_dose_g` | 提醒 | 医生确认后继续 |
| 配伍禁忌（十八反十九畏） | 提醒 | **不阻断** |
| 妊娠禁忌 | 提醒（孕妇时升为强提醒） | 不阻断 |
| 味数异常（> 20 味） | 提醒 | 配置可调 |
| 必填项缺失 | **强制拦截** | 见 R2 |

**R2 饮片处方必填项（契约 §8）。** 处方级：`付数`、`煎法`、`服法`；明细级：每味 `剂量(g)`。
每味 `脚注` 缺省为 `NORMAL`（常规），缺失不拦截但提醒。

**R3 毒性饮片超量的"二次确认"必须留痕。**
流程：返回 `need_confirm=true` + 剂量上限值 → 医生在界面显式勾选确认并填写理由 → 再次提交带
`toxic_confirm=1` 与 `toxic_reason` → 通过并写 `audit_high_risk`（风险类型 `OVERRIDE`）。
**不接受空理由，不接受一次提交同时开方又确认。**

**R4 配伍禁忌只提醒。** 命中 `herb_compatibility` → 记录命中 + 界面提示，**允许医生继续**（R-M06-7）。
医生处置（接受 / 忽略）写入 `prescription_rule_hit.doctor_action`。

**R5 剂量上限提醒的粒度是"每味单剂量"。** 比较 `剂量(g)` 与 `herb.max_dose_g`；
**付数不参与上限判断**（7 付 × 10g 不等于超量）。

**R6 妊娠禁忌分级。** `herb.pregnancy_flag`：`CONTRAINDICATED`（禁用）/ `CAUTION`（慎用）/ 空（无标记）。
患者为育龄女性且病历提示妊娠 → 提级为强提醒；否则仅普通提醒。**一律不阻断。**

**R7 规则命中全部记录。** 同 F35 R7：写入 `prescription_rule_hit`，含规则类型、强度、医生处置、时间。

**R8 提交与确认各跑一次。** 同 F35 R8；确认时若明细或付数已变 → 重跑（AC12）。

**R9 AI 建议不豁免。** 来自 M04 F24 的饮片建议走**完全相同**的校验（R-M06-4）。

**R10 规则服务异常 = 拒绝提交。** 同 F35 R10：校验跑不起来时拒绝提交，不静默放行。

**R11 配伍禁忌表可维护但需审计。** `herb_compatibility` 的增删改属于规则变更，写 `audit_high_risk`（`CONFIG_CHANGE`）。
**不得在开方事务内修改规则表。**

## 5. 验收标准

**AC1（毒性饮片超量强制二次确认）**【关键】
- Given 处方含制川乌 12g（上限 10g），未带确认标记
- When 提交
- Then 返回需二次确认，处方**不进入 PENDING**，提示上限值
- 验证方式：自动

**AC2（二次确认需理由 + 审计）**
- Given 上一步需确认
- When 带 `toxic_confirm=1`、`toxic_reason="患者长期服用耐受"` 重新提交
- Then 通过，写 `audit_high_risk`（OVERRIDE）含理由与剂量
- 验证方式：自动

**AC3（空理由不接受）**
- Given 毒性饮片超量
- When 带 `toxic_confirm=1` 但无理由
- Then 拒绝，提示必须填写理由
- 验证方式：自动

**AC4（剂量超限仅提醒）**
- Given 黄芪 60g（上限 30g），非毒性
- When 提交
- Then 提醒但**允许提交**，记录命中
- 验证方式：自动

**AC5（配伍禁忌提醒不阻断）**【关键】
- Given 处方同时含甘草与甘遂（十八反）
- When 提交
- Then 提示配伍禁忌，但**允许医生继续**，命中已记录
- 验证方式：自动

**AC6（付数不参与剂量上限判断）**
- Given 某味 10g × 7 付，上限 15g
- When 提交
- Then **不触发**剂量超限提醒（总量 70g 不是单剂量）
- 验证方式：自动

**AC7（重复药味强制拦截）**
- Given 同一处方中黄芪出现两次
- When 提交
- Then **拦截**，提示重复药味
- 验证方式：自动

**AC8（必填项缺失拦截）**
- Given 饮片处方缺付数 / 煎法 / 服法之一
- When 提交
- Then **拦截**，指出缺失项
- 验证方式：自动

**AC9（味数异常提醒）**
- Given 处方 22 味（阈值 20）
- When 提交
- Then 提醒味数偏多，不阻断
- 验证方式：自动

**AC10（妊娠禁忌提醒）**
- Given 患者妊娠，处方含妊娠禁用饮片
- When 提交
- Then 强提醒，不阻断，记录命中
- 验证方式：自动

**AC11（AI 建议不豁免）**
- Given AI 建议含毒性超量饮片，医生采纳
- When 提交
- Then 同样要求二次确认
- 验证方式：自动（跨模块，需 M04 配合）

**AC12（确认时重跑）**
- Given 提交后修改了剂量
- When 确认
- Then 重新校验，不使用旧结果
- 验证方式：自动

**AC13（命中记录完整）**
- Given 多次校验
- When 查 `prescription_rule_hit`
- Then 含 rule_type、severity、doctor_action、剂量上限与实际剂量、时间
- 验证方式：自动

## 6. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E3040 | 毒性饮片超量，需二次确认 | 是（确认后） |
| E3041 | 配伍禁忌命中（提醒，不阻断） | 是 |
| E3042 | 饮片处方必填项缺失 | 否 |
| E3045 | 重复药味 | 否 |
| E3046 | 妊娠禁忌命中（提醒） | 是 |
| E3037 | 规则校验服务异常，拒绝提交 | 是 |

---

## 7. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 配伍禁忌表缺失 | 视为"未知"，**提醒未知**而非"无禁忌"，不阻断 |
| 规则服务异常 | 拒绝提交（不静默放行） |
| 崩溃 | 命中记录不半写；重新校验 |
| 二次确认过程中医生改了剂量 | 确认标记失效，需重新确认（绑定当时剂量） |

---

## 8. 契约缺口

- `herb_compatibility` 的初始数据来源需 M14 F128 的基础数据包一并提供（十八反十九畏约 20 组）。
- 妊娠状态目前取自病历文本提示，未建独立字段；若后续需要结构化统计，需在 M03 增加字段（契约变更流程）。
