# F38 处方作废

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: S]

---

## 1. 职责

将未发药的处方作废，释放其占用的金额与库存预留。

---

## 2. 依赖

- 依赖：M09（已收费需退款）、M07（已发药需退药）、M12（`audit_high_risk`）
- 被依赖：M07、M09

---

## 3. 涉及的表

`prescription`（M06 自有）

---

## 4. 规则

**R1 已发药不可作废。** `DISPENSED` / `PARTIAL_RETURNED` 状态**不可作废**，只能走退药（M07 F46）+ 退药退款（M09 F63）。

**R2 作废必须填原因。** 从字典选择（患者放弃 / 医生改方 / 录入错误 / 重复开方 / 其他）+ 备注。写 `audit_high_risk`。

**R3 已收费需先退款。** 若处方金额已计入账单且已支付 → 先走 M09 退款，再作废（或作废时联动退款，二选一实现，但必须保证一致）。

**R4 作废后不可恢复。** VOID 是终态；如需用药必须重新开方。

**R5 作废释放库存预留。** 若开方时预留了库存（可配置是否预留），作废时释放。

**R6 作废不影响已确认病历。** 病历中若引用了该处方，引用保留但标记为已作废处方（M03 F16 类似逻辑）。

**R7 作废金额不计入统计。** 作废处方不计入处方统计（契约 §7），但作废率可统计。

**R8 中药处方可作废。** 饮片/颗粒处方未发药时同样可作废。

---

## 5. 验收标准

**AC1（未发药作废）**
- Given 处方处于 CONFIRMED 未发药
- When 作废并填原因
- Then 状态 VOID，`audit_high_risk` 记录原因
- 验证方式：自动

**AC2（原因必填）**
- Given 不填原因
- When 作废
- Then 拒绝
- 验证方式：自动

**AC3（已发药拒绝作废）**【关键】
- Given 处方已 DISPENSED
- When 尝试作废
- Then 拒绝并提示"已发药，请走退药流程"
- 验证方式：自动

**AC4（已收费联动退款）**
- Given 处方已收费
- When 作废
- Then 触发 M09 退款，账单与处方状态一致
- 验证方式：自动（跨模块，需 M09 配合）

**AC5（作废后不可恢复）**
- Given 处方 VOID
- When 尝试改回 CONFIRMED
- Then 拒绝
- 验证方式：自动

**AC6（库存预留释放）**
- Given 开方时预留了库存（若启用）
- When 作废
- Then 预留释放，可用库存恢复
- 验证方式：自动（跨模块，需 M07 配合）

**AC7（不计入处方统计）**
- Given 今日 10 张处方其中 2 张作废
- When 统计处方数
- Then 为 8
- 验证方式：自动（跨模块，需 M15 配合）

**AC8（中药处方可作废）**
- Given 一张未发药的饮片处方
- When 作废
- Then 成功作废
- 验证方式：自动（跨模块，需 F111 配合）

**AC9（事务性）**
- Given 作废时退款失败
- When 执行
- Then 整体回滚，处方保持原状态
- 验证方式：自动（注入失败）

## 6. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E2001 | 作废原因必填 | 否 |
| E3040 | 已发药不可作废，请走退药 | 否 |
| E3017 | 存在有效收款，请先退款 | 否 |
| E1010 | 审计写入失败 | 是 |

---

## 7. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 退款失败 | 整体回滚；提示先完成退款 |
| 崩溃 | 事务保证；无"已作废但未退款" |
| 误作废 | 不可恢复；重新开方（提示用户） |
