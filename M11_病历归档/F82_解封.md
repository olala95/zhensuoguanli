# F82 解封

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: S]

---

## 1. 职责

对已封存病历执行**解冻**：`SEALED → UNSEALED`，恢复可修改能力，但**解封记录永久保留**（不删除封存痕迹）。属于**高风险操作**。

---

## 2. 依赖

- 依赖：F81（封存）、M12（高风险审计）
- 被依赖：无

---

## 3. 涉及的表

`record_unseal`、`record`（状态经 M03 服务接口推进 `SEALED → UNSEALED`）

---

## 4. 规则

**R1 只有 SEALED 可解封。** 未封存（DRAFT/CONFIRMED/ARCHIVED）拒绝（E3001）；已解封不可重复解封（E3091）。

**R2 必填解封原因。** `reason` 为空拒绝（E2001）；原因进入 `record_unseal` 与审计，**不可留空**。

**R3 写高风险审计。** 每次解封调用 `audit.audit_high_risk`（RISK_OVERRIDE），记录操作人、时间、原因、归档号（03 §9）。

**R4 仅管理员可执行。** 非管理员拒绝（E6002）。

**R5 解封不删除封存记录。** `record_seal` 行保留；`record_unseal` 只追加，形成「封存—解封」成对留痕（R-M11-5）。

**R6 UNSEALED 不可直接再封存。** 解封后**不能原地再次封存**（F81 检查同一归档周期内封存次数），避免「封存—解封」反复切换掩盖篡改；如需再冻结，必须更正后**重新归档（开新归档号）**再封存。

**R7 状态推进经 M03 接口。** `SEALED → UNSEALED` 走 M03 `transition()`，**禁止裸 UPDATE**（R5）。

**R8 解封后重新开放修改（仍留痕）。** 解封后 F77 修改留痕可用；修改照常新建版本并续写 Hash 链（不修补历史）。

**R9 幂等。** 同一 `idempotent_key` 不重复解封。

---

## 5. 验收标准

**AC1（解封成功）**
- Given 已封存病历
- When 管理员解封并填原因
- Then 状态 UNSEALED，`record_unseal` 有记录
- 验证方式：自动

**AC2（未封存不可解封）**
- Given 病历仅 ARCHIVED 未封存
- When 解封
- Then 拒绝 E3001
- 验证方式：自动

**AC3（必填原因）**
- Given 已封存
- When 解封不填原因
- Then 拒绝 E2001
- 验证方式：自动

**AC4（非管理员拒绝）**
- Given 医生角色
- When 解封
- Then 拒绝 E6002
- 验证方式：自动

**AC5（解封记录与封存记录并存）**
- Given 解封完成
- When 查 `record_seal` 与 `record_unseal`
- Then 两条均在，封存记录未被删除
- 验证方式：自动

**AC6（高风险审计落库）**
- Given 解封完成
- When 查高风险审计
- Then 含操作人/时间/原因/归档号
- 验证方式：自动

**AC7（解封后不可原地再封存）**
- Given 已 UNSEALED
- When 再次封存
- Then 拒绝 E3001；重新归档（新归档号）后才可再封存
- 验证方式：自动

**AC8（解封后可修改留痕）**
- Given 已解封
- When 走 F77 修改
- Then 成功并新增版本
- 验证方式：自动（跨 F77）

**AC9（幂等）**
- Given 相同幂等键提交两次
- When 第二次
- Then 不重复解封
- 验证方式：自动

## 6. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E3001 | 状态不允许解封 / 已解封 | 否 |
| E3091 | 重复解封 | 否 |
| E2001 | 未填解封原因 | 否 |
| E6002 | 非管理员解封 | 否 |

---

## 7. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 解封事务中断 | 回滚，可重试（幂等） |
| 误解封 | 不可回滚；只能重新归档+封存，解封记录永久保留 |
