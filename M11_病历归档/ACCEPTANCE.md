# M11 病历归档 · 验收

> 本文只写**跨 F 的端到端场景与故障演练**，单 F 内部的 AC 见各 `Fxx.md`。

---

## 1. 端到端场景

### S1 病历全生命周期（主链路）

```
M03 确认（F19）
  → F76 生成 v1 版本快照 + F80 写 Hash 链首条
  → F78 关闭（closed 标记）
  → F79 归档（AR{yyyyMM}{4位}，CONFIRMED → ARCHIVED）
  → F81 封存（ARCHIVED → SEALED）
```

**判定**：
- [ ] 每个版本一条 `record_hash`，`prev_hash` 严格串联
- [ ] 归档号按月递增、不重复
- [ ] 状态全部经 M03 `transition()`，无裸 UPDATE
- [ ] 封存后 F77 修改、F79 再归档均被拒

### S2 修改留痕闭环（关键）

```
已确认病历需更正 → F77 修改（填原因）
  → 新建 v2 快照（v1 完整保留）→ Hash 链追加 v2（prev = v1.hash）
  → 校验：v1 的 hash 不变，v2 的 prev_hash == v1.hash
```

**判定**：
- [ ] 修改**不改**历史版本内容，只追加
- [ ] 修改留痕含原因/操作人/时间
- [ ] 版本快照自包含，脱离当前内容仍可读（R-M11-7）
- [ ] 修改后 Hash 链仍校验通过

### S3 封存—解封—再冻结

```
封存（SEALED）→ 发现确需更正 → F82 解封（填原因 + 高风险审计）
  → F77 修改（v3）→ 重新归档 → 重新封存
```

**判定**：
- [ ] 解封不删除封存记录，`record_seal` 与 `record_unseal` 成对留存
- [ ] 解封后**不能再次封存**同一状态（需重新走归档），无「封存取巧」路径
- [ ] 解封写 `audit_high_risk`（RISK_OVERRIDE），含操作人/时间/原因/归档号
- [ ] 非管理员解封被拒

### S4 Hash 链防篡改（关键）

```
人为 UPDATE 一条 record_hash → 数据库拒绝 E2006
人为改业务内容 → 批量巡检发现并指出第一条不符位置
链异常时 → 归档/封存/导出全部被拒 E3090 + 高风险审计
```

**判定**：
- [ ] Hash 记录只增不改（触发器）
- [ ] 篡改可被发现且**不自动修复**（转人工核查）
- [ ] 三个关键节点（归档/封存/导出）均强制校验
- [ ] 批量巡检接口可供 M14 健康检查调用

### S5 导出闭环

```
任一状态（CONFIRMED/ARCHIVED/SEALED/UNSEALED）→ F83 导出
  → 先校验 Hash → 写文件 → 记 record_export（不含正文）
```

**判定**：
- [ ] 导出内容取自**最新版本快照**，与版本一致
- [ ] 导出**不改变**病历状态、不新增版本
- [ ] `record_export` 无正文字段，只有路径/格式/大小/时间
- [ ] 路径穿越被拒；链异常拒绝导出

### S6 与上游对齐

```
版本内容      = M03 病历内容（只读，经 M03 服务接口）
版本快照来源  = M03 的 record 主表 + 内容子表序列化
状态推进      = M03 状态机（本模块不直接 UPDATE record.status）
```

**判定**：
- [ ] 本模块不写 M03 拥有的任何表（R2）
- [ ] 管理员全程可封存/解封/导出，但**改不了**已确认病历内容（R-M11-6）
- [ ] 归档/封存/导出均支持幂等键，重复提交不产生第二条记录

## 2. 故障演练

| # | 场景 | 期望 |
|---|---|---|
| M11-1 | 归档事务中断 | 回滚，可重试；不产生半条归档记录 |
| M11-2 | 版本写入成功但 Hash 写入失败 | 同事务回滚，版本与 Hash 不分离 |
| M11-3 | Hash 链被人为破坏 | 归档/封存/导出均拒绝 E3090 + 高风险审计，不自动修复 |
| M11-4 | 尝试 UPDATE `record_hash` / `record_export` | 数据库拒绝 E2006 |
| M11-5 | 重复归档 / 重复封存 / 重复解封 | 拒绝（E3001 / E3091），幂等键下不重复写 |
| M11-6 | 管理员尝试修改已确认病历内容 | 拒绝（R-M11-6），只可走 F77 留痕 |
| M11-7 | 导出目录不存在 / 磁盘满 | 报错，事件不落库，可重试 |
| M11-8 | 解封未填原因 | 拒绝 E2001，不推进状态 |
| M11-9 | 批量巡检发现异常病历 | 返回 valid=false + 首个不符位置，健康检查可见 |
| M11-10 | 归档后上游内容变更 | 归档固化的版本号与快照不变（R-M11-7） |

## 3. 合规与一致性检查

- [ ] `record_hash`、`record_export` 只允许 INSERT（触发器在位）
- [ ] 所有状态推进走 M03 `transition()` 并写状态日志
- [ ] 封存/解封/导出失败场景均写审计，解封必写高风险审计
- [ ] 版本快照自包含，无「追溯改写」路径
- [ ] M11 相关异常码均在 E3090–E3092 区间且标注 `retryable`
- [ ] 跨模块只读：本模块代码无任何对 M03 表的 INSERT/UPDATE/DELETE
