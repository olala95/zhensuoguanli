# F80 Hash

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: M]

---

## 1. 职责

为病历的每个版本生成**链式 Hash**：`hash = sha256(规范序列化(版本快照) ‖ prev_hash)`，使任何对历史版本的篡改都能被校验发现。

---

## 2. 依赖

- 依赖：F76（版本快照）
- 被依赖：F79（归档前置校验）、F81（封存）、M14（健康检查可定期校验）

---

## 3. 涉及的表

`record_hash`

---

## 4. 规则

**R1 算法固定。** SHA-256，十六进制小写；`hash = sha256(canonical_json(snapshot) + prev_hash)`。

**R2 规范序列化。** 键按字典序排序、去除无意义空白、统一字符串编码（UTF-8），**保证同一内容必得同一 Hash**（否则误报篡改）。

**R3 链首 `prev_hash` 为空串。** 首条记录的 prev 为 `""`（不是 NULL），便于校验逻辑统一。

**R4 校验逐条重算。** 校验时从链首重新计算每条并与存储值比对：任一不符 → 该链不可信，**列出第一条不符的位置**。

**R5 只增不改。** `record_hash` 只允许 INSERT（表级触发器）；Hash 错误只能追加新版本，**不得修补历史 Hash**（修补即掩盖篡改）。

**R6 关键节点强制校验。** 归档（F79）、封存（F81）、导出（F83）前**必须**校验；失败 → 拒绝并写 `audit_high_risk`。

**R7 定期巡检。** 提供批量校验接口，供 M14 健康检查/定时任务调用。

---

## 5. 验收标准

**AC1（首条 prev 为空串）**
- Given 创建 v1
- When 查 Hash
- Then `prev_hash` 为 ""
- 验证方式：自动

**AC2（链式依赖）**
- Given v1、v2 两条
- When 查 v2 的 prev_hash
- Then 等于 v1 的 hash
- 验证方式：自动

**AC3（规范序列化稳定）**
- Given 同一快照序列化两次（键顺序不同）
- When 比较 Hash
- Then 完全一致
- 验证方式：自动

**AC4（篡改可被发现）**
- Given 人为改一条 hash 值
- When 校验
- Then 返回 valid=false 且指出第一条不符位置
- 验证方式：自动

**AC5（不可修补历史 Hash）**
- Given 尝试 UPDATE 一条 hash
- When 执行
- Then 数据库拒绝 E2006
- 验证方式：自动

**AC6（归档前强制校验）**
- Given 链被破坏
- When 归档
- Then 拒绝 E3090
- 验证方式：自动（跨 F79）

**AC7（封存前校验）**
- Given 链正常
- When 封存
- Then 校验通过并封存成功
- 验证方式：自动（跨 F81）

**AC8（批量巡检）**
- Given 多份病历
- When 调批量校验
- Then 返回每份的校验结果与异常清单
- 验证方式：自动

---

## 6. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E2006 | 尝试修改 Hash 记录 | 否 |
| E3090 | Hash 链校验失败 | 否 |

---

## 7. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 校验发现篡改 | 拒绝后续动作 + 高风险审计 + 转人工核查（**不自动修复**） |
| 写入中断 | 与版本同事务回滚 |
