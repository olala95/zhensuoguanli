# M10 打印与硬件

> 阶段：第四阶段  
> 依赖：M02（Visit）、M06（处方与饮片明细）、M07（发药/批次/用法）、M09（账单与支付）、M14、M12  
> 被依赖：M11（归档导出可带走打印件）、UI

---

## 1. 模块职责

把业务单据变成可打印的凭证并送到硬件：处方笺（含**中药饮片方**）、收费凭条、药袋标签；以及本地硬件能力（身份证读取、扫码枪、硬件监控）。

**两条硬约束**：

- 打印失败可重打，且**重打不产生新单据号**（03 §2.7 / F70）
- 硬件不可用必须**降级不阻塞主流程**（E4xxx 一律 `retryable=true` 且有降级路径）

## 3. 模块级规则

**R-M10-1 打印任务化。** 任何打印都先落 `print_job`，再由执行器送硬件；**不允许直接调驱动打印**（否则无法重打、无法审计）。

**R-M10-2 模板与数据分离。** 模板存文本 + 占位符（`{{field}}`），渲染在任务创建时完成并**固化渲染结果**（`rendered_text`），重打时用同一份渲染结果，**不重新取数**（保证重打件与原件一致）。

**R-M10-3 重打不换单号。** 重打印在原任务上 `reprint_count + 1` 并写重打标记，**不生成新 `print_job_no`**（03 §2.7）。

**R-M10-4 状态机（03 §2.7）。**

```
PENDING → PRINTING → SUCCESS | FAILED
FAILED → RETRYING → PRINTING
FAILED → ABANDONED（超过重试上限或人工放弃）
```

每次转换写 `print_status_log`，禁止裸 UPDATE。

**R-M10-5 驱动可注入（R8）。** 所有硬件经 `core/hardware.py` 的驱动注册表中转，内置 **mock 驱动**（落盘/返回模拟数据），真实设备由外部 Hardware Agent 提供同名驱动替换。至少一条 AC 走 mock 路径。

**R-M10-6 硬件失败降级。** 打印机离线/缺纸（E4001）、Agent 不可达（E4002）→ 任务 FAILED 但**业务不回滚**（处方已确认、钱已收，不能因为打不出纸就退回）；提示可稍后重打。

**R-M10-7 重试上限可配。** `print.max_retry`（默认 3）；超限 → `ABANDONED` 并写 `audit_high_risk`（凭证缺失属风险事件）。

**R-M10-8 Hardware Agent 不直连业务库（05 §2）。** Agent 若有独立进程，一律通过本地 IPC 调主程序接口；本模块对外只暴露主程序侧接口。

**R-M10-9 硬件事件留痕。** 身份证读取、扫码、心跳、故障均写 `hardware_event`；身份证读取**不落库患者隐私**，只返回给调用方用于填表。

**R-M10-10 幂等。** 同一业务单据 + 同一模板的重复打印请求可带 `idempotent_key`，避免重复排队。

| 接口                          | 说明              | 消费方            |
| --------------------------- | --------------- | -------------- |
| `print.prescription(rx_id)` | 处方笺（成药/饮片自动选模板） | M06 UI、M07 发药后 |
