# M10 打印与硬件 · 验收

> 本文只写**跨 F 的端到端场景与故障演练**，单 F 内部的 AC 见各 `Fxx.md`。

## 1. 端到端场景

### S1 主流程三张凭证

```
处方确认 → 收费 → 发药
   → 处方笺（F67，成药/饮片自动选模板）
   → 收费凭条（F68）
   → 药袋标签（F69）
```

**判定**：
- [ ] 三张凭证都是 `print_job`，单号均为 `PJ{yyyyMMddHHmmss}{3位}`
- [ ] 饮片方必含每味剂量与脚注、付数、煎法、服法
- [ ] 凭条金额与账单一致（含冲正负数行）
- [ ] 打印失败**不回滚**处方确认、收款、库存扣减

### S2 失败与重打闭环（关键）

```
打印失败（离线/缺纸）→ FAILED + print_failure（retryable）
   → 自动重试 ≤ max_retry → 仍失败 → ABANDONED + 高风险审计
   → 恢复后重打（F70）→ 成功，单号不变、内容与首次一致
```

**判定**：
- [ ] 重打**不产生新任务号**，只累加 `reprint_count`
- [ ] 重打用首次固化的 `rendered_text`，不重新取数
- [ ] 重打不产生任何业务单据（不发药、不收费）
- [ ] 超限放弃写高风险审计

### S3 硬件降级与恢复

```
扫码枪离线 → 扫码抛 E4001（可重试）→ UI 降级为手工输入 → 建档/入库继续
   → 监控发现连续失败（F75）→ 看门狗重新初始化驱动（F98）→ 恢复 ONLINE
```

**判定**：
- [ ] 硬件失败一律 `retryable=true` 且业务可继续（不阻塞主流程）
- [ ] 身份证读取不落库隐私原文
- [ ] 发药扫码核对不一致报警并写高风险审计
- [ ] 驱动可注入替换（至少一条 AC 走 mock）

### S4 与上游对齐

```
处方打印内容 = M06 处方与计价结果
凭条内容     = M09 账单明细与支付
标签内容     = M07 发药记录（代煎/自煎、可取时间）
```

**判定**：
- [ ] 三处金额口径一致（分 → 元，2 位）
- [ ] 未确认处方 / 未收费账单 / 未发药处方均拒绝打印凭证

## 2. 故障演练

| # | 场景 | 期望 |
|---|---|---|
| M10-1 | 打印中途断电/缺纸 | 任务可重打，**不产生新单据号**，有重打标记 |
| M10-2 | 驱动抛异常 | 任务 FAILED + `print_failure`，业务状态不变 |
| M10-3 | 重试超过上限 | 转 ABANDONED 并写高风险审计 |
| M10-4 | 模板缺失 | 拒绝 E7001 且 `retryable=false` |
| M10-5 | 重打超过 max_reprint | 仍允许但写高风险审计 |
| M10-6 | 硬件 Agent 崩溃 | 心跳连续失败 → 看门狗重新初始化 → 未完成任务不丢 |
| M10-7 | 打印成功但业务已变更 | 重打内容仍与首次一致（固化文本） |

## 3. 合规与一致性检查

- [ ] 所有打印都经 `print_job`，不存在直接调驱动的路径
- [ ] 打印状态转换全部走状态机并写 `print_status_log`
- [ ] 硬件事件不含患者隐私原文
- [ ] 凭证缺失（ABANDONED）在健康检查中可见
- [ ] 打印与硬件相关异常码均为 E4xxx / E7xxx 且标注 `retryable`
