# F75 硬件监控

[TYPE: JOB] [PRIORITY: P2] [SIZE: S]

---

## 1. 职责

定期探测硬件状态并落心跳：发现离线/降级时更新设备状态、写事件、供健康检查与看门狗消费。

---

## 2. 依赖

- 依赖：F72（驱动）、M14（健康检查 F105/诊断 F104）
- 被依赖：F98（Hardware Agent 看门狗）、M14 健康状态展示

---

## 3. 涉及的表

`hardware_health`（心跳）、`hardware_device`（状态）、`hardware_event`

---

## 4. 规则

**R1 心跳周期可配。** `hardware.heartbeat_seconds`（默认 60）；由定时任务或每次调用时惰性检查触发。

**R2 状态判定。** 心跳成功 → `ONLINE`；失败 → `OFFLINE`；连续失败但未超限 → `DEGRADED`。

**R3 心跳留痕。** 每次探测写 `hardware_health`（设备、结果、耗时、时间），供趋势查看。

**R4 只观测不改业务。** 监控不改变任何业务数据；不自动重打印、不自动重发。

**R5 看门狗消费。** 连续失败达到 `hardware.watchdog_fail_threshold`（默认 3）→ 通知 F98 重新初始化驱动。

**R6 纳入健康检查。** M14 F105 读取最近硬件状态，展示在"系统诊断/健康检查"里。

**R7 日志可轮转。** 心跳属监控数据，量大时可清理（与系统日志同策略），**不是审计数据**。

---

## 5. 验收标准

**AC1（心跳写入）**
- Given 触发一次监控
- When 查 `hardware_health`
- Then 每个启用设备一条心跳记录
- 验证方式：自动

**AC2（成功置 ONLINE）**
- Given 驱动正常
- When 探测
- Then 设备状态 ONLINE
- 验证方式：自动

**AC3（失败置 OFFLINE）**
- Given 驱动配置为失败
- When 探测
- Then 状态 OFFLINE，写事件
- 验证方式：自动（mock）

**AC4（连续失败触发看门狗阈值）**
- Given 连续失败达到阈值
- When 探测
- Then 标记需要重启（供 F98 消费）
- 验证方式：自动（跨 F98）

**AC5（不改业务）**
- Given 触发多次监控
- When 查处方/账单/库存
- Then 无变化
- 验证方式：自动

**AC6（可被健康检查读取）**
- Given 已产生心跳
- When 调健康检查
- Then 返回硬件状态摘要
- 验证方式：自动（跨 M14）

| 码 | 场景 | 可重试 |
|---|---|---|
| E4001 | 设备离线 | 是 |
| E4002 | 驱动不可达 | 是 |

## 7. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 探测失败 | 记录并交由看门狗处理，不影响业务 |
| 心跳表过大 | 提供清理接口，按保留天数删除 |
