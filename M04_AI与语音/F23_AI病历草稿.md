# F23 AI 病历草稿

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: M]

---

## 1. 职责

基于事实提取结果（F22）生成病历各字段的草稿文本，供医生审核、修改后写入正式病历。

**本功能是 AI 链路的核心交付物，也是"AI 不得直接落业务库"规则的关键关口。**

---

## 2. 依赖

- 依赖：F22（事实）、**M03 的 `ai.draft.apply()` 接口（第一阶段已冻结）**、F26
- 被依赖：M03 病历（F10/F11/F15）

---

## 3. 涉及的表

`ai_task`、`ai_draft`（M04 自有）
**写入 `record` 必须通过 M03 接口，禁止直接写**

---

## 4. 规则

**R1 草稿只入 `ai_draft`。** 生成的内容**只能**写入 `ai_draft` 表，写入正式 `record` 必须通过 M03 的 `ai.draft.apply()`，且必须由医生确认。

**R2 分字段生成。** 分别生成主诉、现病史、既往史、查体等字段草稿，医生可**逐字段**采纳/修改/丢弃，不支持"整份一键采用"绕过逐项确认。

**R3 生成内容标注来源。** 每个字段标注：AI 生成 / 基于医生修正的事实。医生修改后标记转为 `AI_MODIFIED`。

**R4 不生成舌脉与证型。** 中医四诊（F108）与辨证（F109）**不在生成范围**（R-M04-3）。中医模式下这些字段留空由医生填。

**R5 不生成诊断结论。** 诊断（F17）不生成；可给出候选诊断供参考但必须医生确认。

**R6 草稿可多次生成。** 医生可修改事实后重新生成；新草稿不覆盖旧草稿（保留历史便于对比），医生选择采用哪一份。

**R7 应用后来源标记固化。** 通过 `ai.draft.apply()` 写入 M03 时，来源标记随之固化，M03 确认（F19）后**归档不可消除**。

**R8 应用人记录。** `ai_draft` 记录 `applied_by`（应用的医生）与 `applied_at`；审计中的操作人是该医生，**不是 AI 也不是 system**（R-M04-10）。

**R9 生成失败可降级。** 草稿生成失败 → 医生手工书写，不阻塞。

**R10 草稿展示需区分。** 界面上 AI 草稿与医生手写内容**视觉可区分**（如底色或角标），避免医生误以为是自己的内容。

## 5. 验收标准

**AC1（分字段生成）**
- Given 已提取若干事实
- When 生成草稿
- Then 主诉、现病史等字段分别生成，可逐字段操作
- 验证方式：自动（mock 生成服务）

**AC2（不直接写业务库）**【关键】
- Given 草稿已生成
- When 检查 `record` 表
- Then **无任何内容**；确认后才通过 M03 接口写入
- 验证方式：自动（跨模块）

**AC3（逐字段采纳）**
- Given 生成了主诉与现病史草稿
- When 医生采纳主诉、修改现病史、丢弃查体
- Then 主诉标 AI、现病史标 AI_MODIFIED、查体不被应用
- 验证方式：自动

**AC4（来源标记固化）**
- Given 应用草稿后医生确认病历（F19）
- When 查看病历
- Then 来源标记已固化，**归档后不可消除**
- 验证方式：自动（跨模块，需 M03/M11 配合）

**AC5（不生成舌脉证型）**
- Given 中医模式下生成草稿
- When 查看草稿
- Then 四诊与证型字段为空，由医生填写
- 验证方式：自动

**AC6（不生成诊断）**
- Given 生成草稿
- When 查看诊断字段
- Then 不自动填入诊断（可给候选但需确认）
- 验证方式：自动

**AC7（多次生成保留历史）**
- Given 生成草稿后修改事实再生成
- When 查看
- Then 存在两份草稿，可选择采用哪份
- 验证方式：自动

**AC8（应用人是医生）**
- Given 医生 B 应用了草稿
- When 查看审计
- Then 操作人为 B，不是 AI/system；`ai_draft.applied_by` = B
- 验证方式：自动

**AC9（生成失败降级）**
- Given 生成服务不可用
- When 触发生成
- Then 任务 FAILED，医生可手工书写，不阻塞
- 验证方式：自动

**AC10（界面可区分）**
- Given 草稿内容展示在病历编辑器
- When 查看
- Then AI 生成内容与医生手写内容视觉可区分
- 验证方式：自动（UI 断言）

**AC11（崩溃恢复）**
- Given 草稿生成中强杀
- When 重启
- Then 任务状态明确可重试；`ai_draft` 无半写内容
- 验证方式：自动

---

## 6. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E5001 | 网络不可达 | 是 |
| E5003 | 生成超时 | 是 |
| E5004 | 返回不可解析 | 是 |
| E5006 | 生成内容不合规（含诊断结论等） | 是（重新生成） |
| E6006 | 未经医生确认尝试写入正式病历 | 否 |

---

## 7. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 生成失败 | FAILED + 可重试；降级手工 |
| 生成内容不合规（如擅自生成诊断） | 拦截该内容，标记 `E5006`，不写入 `ai_draft` 的诊断字段 |
| 应用过程崩溃 | 事务回滚；草稿仍存在可重新应用 |
| 崩溃 | F26 管理任务状态与幂等重试 |
