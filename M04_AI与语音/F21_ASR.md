# F21 ASR（语音转文字）

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: M]

---

## 1. 职责

将录音转写为文本，并做基础的角色区分（医生/患者）与标点处理。

---

## 2. 依赖

- 依赖：F20（录音文件）、F26（任务管理与失败恢复）、M14（配置：ASR 服务端点、超时）
- 被依赖：F22（事实提取的输入）

---

## 3. 涉及的表

`ai_task`、`ai_transcript`（M04 自有）

---

## 4. 规则

**R1 转写是异步任务。** 通过 `ai_task` 管理，UI 显示进度，不阻塞医生操作。

**R2 转写结果可编辑。** 转写文本**必须可人工修正**后再进入 F22 事实提取。医生可在转写文本上直接改错字，改后重新提取。

**R3 角色区分尽力而为。** 若 ASR 支持说话人分离，标注医生/患者；不支持则整段文本，不做区分标记（不臆测）。

**R4 医疗术语优化。** 若 ASR 服务支持热词/术语表，加载药品名、症状名等词典提升准确率。**术语表由基础数据包（F128）与药品字典提供。**

**R5 本地/云端双路径。** 支持本地 ASR 与云端 ASR 两种实现，由配置切换。云端需 `ai.allow_upload=1`。

**R6 失败可重试。** 失败后允许手动重试；重试次数与退避策略由 F26 统一管理。

**R7 转写文本入库并留痕。** `ai_transcript` 保存原始转写与医生修正后文本（两版本都保留），修正动作留痕。

**R8 超时明确。** 超时（默认 60s，可配）后任务标记 FAILED，UI 明确提示"转写超时，可重试或手工录入"。

**R9 不因 ASR 失败阻塞流程。** 医生可跳过转写直接手工写病历（R-M04-4）。

**R10 隐私。** 转写文本属患者隐私；上传云端需配置开启；诊断包导出不含转写原文（F104）。

## 5. 验收标准

**AC1（基本转写）**
- Given 一段 2 分钟录音，ASR 服务可用
- When 触发转写
- Then `ai_task` 创建并推进到 SUCCEEDED，`ai_transcript` 含转写文本
- 验证方式：自动（mock ASR 服务）

**AC2（转写可编辑）**
- Given 转写结果中"咳嗽"被误识为"刻手"
- When 医生修正为"咳嗽"并保存
- Then 原始转写与修正后文本都保留，修正留痕
- 验证方式：自动

**AC3（修正后可重新提取）**
- Given 修正了转写文本
- When 重新触发 F22 事实提取
- Then 基于修正后文本提取，结果随之改善
- 验证方式：自动

**AC4（角色区分）**
- Given ASR 返回说话人信息
- When 查看转写
- Then 医生与患者话语分别标注
- 验证方式：自动（mock 返回分离结果）

**AC5（不支持分离时不臆测）**
- Given ASR 不返回说话人信息
- When 查看转写
- Then 整段文本，**无角色标注**
- 验证方式：自动

**AC6（ASR 服务不可用降级）**
- Given ASR 服务不可达
- When 触发转写
- Then 任务 FAILED，UI 明确提示；医生可手工录入病历，**流程不阻塞**
- 验证方式：自动（mock 服务不可达）

**AC7（超时处理）**
- Given ASR 响应超过超时阈值
- When 等待
- Then 任务标记 FAILED（超时码），可重试
- 验证方式：自动（mock 慢响应）

**AC8（重试不重复）**
- Given 转写失败后重试 3 次
- When 检查 `ai_transcript`
- Then 只有一条最终记录，不产生 3 条重复（幂等）
- 验证方式：自动

**AC9（云端上传开关）**
- Given `ai.allow_upload=0`
- When 触发云端 ASR
- Then 拒绝上传，提示需管理员开启；本地 ASR 可用则用本地
- 验证方式：自动

**AC10（崩溃恢复）**
- Given 转写任务执行中强杀进程
- When 重启
- Then 任务状态明确（RUNNING 超时后转 FAILED 或可恢复），可重试；无重复转写
- 验证方式：自动

**AC11（诊断包不含转写）**
- Given 存在转写文本
- When 导出诊断包
- Then 包内不含转写原文
- 验证方式：自动（跨模块）

---

## 6. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E5001 | 网络不可达 | 是 |
| E5003 | ASR 服务超时 | 是 |
| E5004 | ASR 返回不可解析 | 是 |
| E5005 | 未开启云端上传 | 否 |

---

## 7. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 网络中断 | 任务 FAILED，可重试；重试由 F26 管理 |
| 服务返回乱码 | 标记 `E5004`，保留原始响应供排查；不写入 `ai_transcript` |
| 崩溃 | 任务状态由 F26 的看门狗/超时机制纠正；重试幂等 |
