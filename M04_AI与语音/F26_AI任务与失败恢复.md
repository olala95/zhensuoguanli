# F26 AI 任务与失败恢复

[TYPE: SERVICE] [PRIORITY: P0] [SIZE: **L — 已拆分为 4 个子项**]

---

## 1. 职责

统一管理所有 AI 任务的生命周期：创建、执行、重试、超时、放弃、状态纠正，以及 Worker 崩溃后的任务恢复。

**这是 AI 链路可靠性的兜底。AI 功能可以失败，但任务状态不能错乱，数据不能半写。**

## 5. 规则

### F26.1 任务模型与幂等

**R1 每个任务有唯一幂等键。** `idempotency_key` 由"业务上下文 + 任务类型 + 触发批次"生成。相同幂等键重复提交**只执行一次**，返回已有结果。

**R2 状态机严格。** `CREATED → RUNNING → SUCCEEDED | FAILED → RETRYING → RUNNING`，超上限 → `ABANDONED`。状态变更写日志。

**R3 超时可配。** 默认 60s（`ai.timeout_ms`）。超时任务标记 FAILED 并记录 `ai_failure_log`。

**R4 任务携带完整上下文。** 任务记录含：类型、关联 Visit、输入引用（录音/文本 ID）、重试次数、耗时、错误码。便于排查。

**R5 结果可查询。** 提供 `ai.taskStatus(taskId)`，UI 可轮询展示进度。

### F26.2 重试与退避

**R6 指数退避。** 重试间隔按指数退避（如 2s / 4s / 8s），最大重试次数可配（默认 3）。

**R7 区分可重试与不可重试。** 网络/超时/5xx → 可重试；参数错误/内容不合规 → 不可重试（重试无意义）。

**R8 人工重试。** 自动重试耗尽后，允许医生手动重试；手动重试重置计数但有上限（防止无限刷）。

**R9 重试不产生重复数据。** 幂等键保证重试不重复写入 `ai_transcript` / `ai_draft` 等结果表。

### F26.3 崩溃恢复与状态纠正

**R10 Worker 崩溃后的状态纠正。** 重启时扫描处于 `RUNNING` 的任务：
- 若已超过超时时间 → 置 FAILED（超时）
- 若仍在超时窗口内 → 置为可重试（RETRYING）
- **不允许长期停留在 RUNNING**（僵尸任务）

**R11 僵尸任务清理。** 启动时执行状态纠正；运行中周期性检测（配合 F97 看门狗心跳）。

**R12 结果不半写。** 任务结果的写入在事务内；崩溃后不存在"任务成功但结果为空"或"结果半写"的状态。校验：任务 SUCCEEDED 时结果表必须有对应记录。

**R13 看门狗联动。** `F97` 负责拉起 Worker 进程；`F26.3` 负责纠正任务状态。二者职责分离但必须都实现。

### F26.4 降级与提示

**R14 降级总原则（R-M04-4）。** 任何 AI 能力不可用，**不得阻塞**接诊、写病历、开处方、收费。医生始终可以纯手工完成全流程。

**R15 提示必须明确。** 不可用时提示："XX 服务不可用，您可继续手工操作"，**不静默失败**。

**R16 降级不降级硬规则。** AI 不可用 ≠ 规则校验失效。M06 的过敏拦截、剂量校验等硬规则**与 AI 无关，永远执行**。

**R17 失败日志完整。** `ai_failure_log` 记录：任务 ID、失败阶段、错误码、响应摘要、重试次数、时间。供 F104 诊断使用。

## 6. 验收标准

### F26.1

**AC1（幂等）**
- Given 同一录音重复提交 3 次转写（相同幂等键）
- When 执行
- Then 只产生 1 个任务、1 条转写结果
- 验证方式：自动

**AC2（状态机）**
- Given 一个任务
- When 依次经历成功/失败/重试
- Then 状态流转符合定义，每次变更有日志
- 验证方式：自动

**AC3（超时）**
- Given 任务执行超过超时阈值
- When 检查
- Then 置 FAILED（超时码），写入 `ai_failure_log`
- 验证方式：自动（mock 慢响应）

### F26.2

**AC4（自动重试）**
- Given 服务返回 5xx 可重试错误
- When 执行
- Then 按退避策略重试至上限（默认 3 次）
- 验证方式：自动

**AC5（不可重试不重试）**
- Given 参数错误类失败
- When 执行
- Then 直接 FAILED，**不重试**
- 验证方式：自动

**AC6（重试不重复）**
- Given 前 2 次失败第 3 次成功
- When 检查结果表
- Then 只有 1 条最终结果
- 验证方式：自动

**AC7（人工重试）**
- Given 自动重试耗尽
- When 医生手动重试
- Then 可重新执行；有上限防止无限刷
- 验证方式：自动

### F26.3

**AC8（Worker 崩溃后状态纠正）**【关键】
- Given 任务处于 RUNNING 时 Worker 崩溃
- When 重启
- Then 超时任务置 FAILED，未超时任务可重试；**无僵尸 RUNNING 任务**
- 验证方式：自动（kill 注入）

**AC9（结果与状态一致）**
- Given 扫描全部 SUCCEEDED 任务
- When 校验结果表
- Then 每个都有对应结果记录；不存在"成功但无结果"
- 验证方式：自动

**AC10（结果与状态一致·反向）**
- Given 扫描结果表中有内容的任务
- When 校验任务状态
- Then 均为 SUCCEEDED；不存在"有结果但任务失败"
- 验证方式：自动

**AC11（崩溃时事务性）**
- Given 结果写入执行中强杀
- When 重启
- Then 任务不处于 SUCCEEDED（或结果与状态一致），可重试
- 验证方式：自动

### F26.4

**AC12（全链路降级）**【关键】
- Given 全部 AI 服务不可用（断网）
- When 完成一次完整接诊：写病历 → 开方 → 收费
- Then **全部流程可用**（纯手工），仅在相应位置提示 AI 不可用
- 验证方式：自动（断网）

**AC13（降级不降级硬规则）**【关键】
- Given AI 不可用且患者过敏
- When 开含过敏药品的处方
- Then M06 规则**仍强制拦截**
- 验证方式：自动（跨模块）

**AC14（失败日志完整）**
- Given 多次失败
- When 查看 `ai_failure_log`
- Then 含任务 ID、阶段、错误码、响应摘要、重试次数、时间
- 验证方式：自动

**AC15（看门狗联动）**
- Given Worker 进程被杀
- When 等待
- Then F97 自动拉起；随后 F26.3 纠正任务状态
- 验证方式：自动（跨模块，需 F97 配合）

## 7. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E5001 | 网络不可达 | 是 |
| E5002 | AI Worker 进程异常 | 是（看门狗拉起） |
| E5003 | 任务超时 | 是 |
| E5004 | 返回不可解析 | 是 |
| E5006 | 内容不合规 | 否 |
| E5007 | 重试次数耗尽 | 否（可人工重试） |

---

## 8. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| Worker 崩溃 | F97 拉起 + F26.3 状态纠正 |
| 网络长期不可用 | 任务最终 ABANDONED；界面降级到手工；网络恢复后可重试 |
| 任务状态错乱 | 启动时执行一次性状态纠正；提供管理员"重置僵尸任务"入口（写 `audit_high_risk`） |
| 磁盘满导致结果无法写入 | 任务 FAILED；提示清理；不半写 |
