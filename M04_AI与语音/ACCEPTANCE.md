## 1. 端到端场景

### S1 语音到病历的完整链路（F20 → F21 → F22 → F23 → M03 F19）
1. 医生点击录音，录入 2 分钟医患对话
2. 停止录音 → 自动触发 ASR 转写
3. 医生修正转写中的错字
4. 事实提取 → 医生逐条审核（采纳/修改/丢弃）
5. 生成病历草稿 → 医生逐字段采纳/修改
6. 应用草稿到正式病历（走 M03 `ai.draft.apply()`）
7. 补充舌脉与诊断（AI 不生成的部分）
8. 确认签名

**通过标准**：
- 草稿未确认前 `record` 表为空（AC2 of F23）
- 最终病历中 AI 生成与医生修改部分**标记可区分且归档后不可消除**
- 审计中的操作人是医生 B，不是 AI/system

### S2 中医场景下的 AI 边界（F23 → F108/F109）
1. 语音录入 → 生成草稿
2. 检查：草稿中不含舌象、脉象、证型、诊断
3. 医生手工填写四诊与辨证
4. 确认

**通过标准**：AI 不越界生成诊断结论与舌脉。

### S3 AI 处方建议与规则校验（F24 → M06）
1. 诊断为 J06.9 → 生成处方建议
2. 医生采纳其中一条
3. 检查：走 M06 完整开方流程与规则校验
4. 构造过敏冲突场景 → 即使来自 AI 建议也被强制拦截

**通过标准**：AI 建议不豁免任何规则；不写入处方表直到医生确认。

### S4 全链路降级（F26.4）
1. 断网（AI 全部不可用）
2. 完成一次完整接诊：手工写病历 → 手工开方 → 收费
3. 检查：流程不阻塞；硬规则仍执行

**通过标准**：核心业务 100% 可离线完成。

## 2. 故障场景（本模块专属）

### FA1 ASR 中途断网
- 操作：转写执行中断网
- 期望：任务 FAILED（可重试）；医生可手工录入；不阻塞
- 通过标准：状态明确，无僵尸任务，可重试成功

### FA2 Worker 进程崩溃
- 操作：任务 RUNNING 时 kill Worker
- 期望：F97 看门狗拉起；F26.3 纠正任务状态；无僵尸 RUNNING
- 通过标准：任务最终状态明确，结果与状态一致（AC8–AC10）

### FA3 重试耗尽
- 操作：mock 服务持续失败
- 期望：重试至上限后 ABANDONED，明确提示，可人工重试
- 通过标准：不无限重试；有人工出口

### FA4 应用草稿时崩溃
- 操作：草稿写入正式病历的事务执行中强杀
- 期望：事务回滚；草稿仍在；可重新应用
- 通过标准：无半写病历

### FA5 磁盘满
- 操作：磁盘写满时录音与保存结果
- 期望：明确 `E1002`，不半写；清理后可继续
- 通过标准：无静默失败

### FA6 时间异常下的任务超时判定
- 操作：系统时间跳变后检查 RUNNING 任务
- 期望：超时判定不因时间跳变误判（结合启动时间/单调时钟）
- 通过标准：不误杀正常任务，不遗漏真超时任务

## 3. 跨模块契约检查

| 检查项 | 期望 |
|---|---|
| 不直接写业务库 | AI 产出只入 `ai_draft`，经 M03 接口且医生确认后才入 `record` |
| 单写者 | AI Worker 不打开业务数据库，全部走 IPC 调主程序 |
| 来源标记 | 三态标记随确认固化，归档后不可消除 |
| AI 不越界 | 不生成舌象、脉象、证型、诊断结论 |
| 规则不豁免 | AI 建议走完整 M06 规则校验；AI 不可用时硬规则仍执行 |
| 审计操作人 | 审计中的操作人是确认医生，不是 AI/system |
| 看门狗 | F97 与本模块同时上线 |
