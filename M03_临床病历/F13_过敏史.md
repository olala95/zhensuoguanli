# F13 过敏史

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: M]

> **本功能是安全红线功能。** 过敏记录直接参与处方规则校验（M06 F35/F113），记录错误或缺失可能导致严重医疗事故。

---

## 1. 职责

记录患者药物/食物/其他过敏原及过敏反应表现，并在接诊与开方环节强制展示与校验。

---

## 2. 依赖

- 依赖：M01（患者，跨就诊共享）、M12、M14（`sys_dict` 过敏原字典）
- 被依赖：**M06 处方规则**（关键消费方）、M02 工作台（顶部常驻）、M08 处置

---

## 3. 涉及的表

`record_allergy`（M03 自有）

> 过敏史**挂在患者维度**（跨就诊共享），而非单次就诊。表中同时记录首次记录时间与最近核实时间。

---

## 4. 规则

**R1 三态明确。** 每个患者的过敏史必须处于三种状态之一：
- `RECORDED`（已记录过敏原）
- `CONFIRMED_NONE`（已确认无过敏）
- `NOT_COLLECTED`（未采集）

**不允许空状态**——空值会导致处方规则误判为"无过敏"。

**R2 未采集必须提示。** 状态为 `NOT_COLLECTED` 时，工作台顶部与开方界面**强制提示采集**，但不阻断开方（急诊场景）。

**R3 过敏原结构化。** 优先从字典选择（青霉素类、头孢类、磺胺类、阿司匹林、中药饮片…），允许手工补充。结构化才能被处方规则自动匹配。

**R4 分级。** 记录过敏反应严重程度：轻度（皮疹）/ 中度（呼吸困难）/ 重度（过敏性休克）。重度过敏在开方时**红色高危提醒**。

**R5 跨就诊共享与核实。** 过敏史跟随患者，每次就诊自动带出；每次就诊需医生**确认或更新**，记录 `last_verified_at` 与核实人。

**R6 修改留痕且有历史。** 删除或下调某条过敏记录必须有原因，且保留历史记录（不物理删除）——避免"曾经过敏后来被删掉"的风险。

**R7 工作台常驻展示。** 通过 `allergy.list(patientId)` 接口向 M02 工作台提供数据，红色常驻展示，**不依赖医生主动查看**。

**R8 处方规则消费。** M06 开方时用本数据校验：命中过敏原 → 强制拦截（不是仅提醒）。详见 M06 F35。

**R9 中药过敏同样记录。** 中药饮片/中成药过敏通过同一结构记录（过敏原字典含中药分类）。

---

## 5. 验收标准

**AC1（三态明确）**
- Given 患者未采集过敏史
- When 查看
- Then 状态为 `NOT_COLLECTED`，界面强制提示采集
- 验证方式：自动

**AC2（确认无过敏）**
- Given 医生确认患者无过敏
- When 标记"确认无过敏"
- Then 状态 `CONFIRMED_NONE`，记录核实人与时间，不再提示采集
- 验证方式：自动

**AC3（结构化记录）**
- Given 录入青霉素过敏（中度）
- When 保存
- Then 过敏原来自字典、分级正确，可在处方规则中被匹配
- 验证方式：自动

**AC4（跨就诊共享）**
- Given 上次就诊记录青霉素过敏
- When 本次就诊打开
- Then 自动带出，要求医生确认或更新
- 验证方式：自动

**AC5（核实留痕）**
- Given 本次就诊确认了过敏史
- When 查看记录
- Then `last_verified_at` 与核实人更新为本次
- 验证方式：自动

**AC6（工作台常驻）**
- Given 患者有重度过敏
- When 打开接诊工作台
- Then 顶部红色常驻展示过敏信息
- 验证方式：自动（跨模块，需 M02 配合）

**AC7（处方强制拦截）**
- Given 患者青霉素过敏
- When 开含青霉素类药品的处方
- Then **强制拦截**（非仅提醒），需医生显式说明理由才能继续，且写 `audit_high_risk`
- 验证方式：自动（跨模块，需 M06 配合）

**AC8（删除留历史）**
- Given 删除一条过敏记录
- When 填原因删除
- Then 该记录标记删除但历史保留，可追溯；写审计
- 验证方式：自动

**AC9（中药过敏）**
- Given 记录对某中药饮片过敏
- When 开含该饮片的处方
- Then 同样触发强制拦截
- 验证方式：自动（跨模块，需 M06/F113 配合）

**AC10（患者合并时保留）**
- Given 合并两名患者（M01 F04）
- When 双方过敏史不同
- Then **并集保留**，不丢弃任何一方的过敏记录
- 验证方式：自动（跨模块）

## 6. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E2001 | 过敏原或分级必填 | 否 |
| E3019 | 过敏史未采集（提示但不阻断） | 是 |
| E3020 | 处方命中过敏原，强制拦截 | 否（需显式说明） |
| E1010 | 审计写入失败 | 是 |

---

## 7. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 过敏查询接口失败 | **开方环节降级为"强制提示未采集"并阻断自动校验**（安全方向降级），不允许降级为"视为无过敏" |
| 保存失败 | 保留内容重试 |
| 崩溃 | 草稿机制保护 |

**关键原则：过敏相关功能的任何失败都必须向"更谨慎"方向降级，绝不能向"视为无过敏"降级。**

---

## 8. 契约缺口

- 需 M06 明确消费本接口的过敏匹配规则（同通用名、同类药物、交叉过敏），契约在 M06 开发时冻结。
