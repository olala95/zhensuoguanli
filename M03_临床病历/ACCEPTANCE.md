## 1. 端到端场景

### S1 一次完整的西医病历（F10→F19）
1. 接诊 → 录主诉"咳嗽 3 天"
2. 录现病史（含起病、演变、伴随症状）
3. 既往史自动带出上次记录，医生确认
4. 过敏史标记"确认无过敏"
5. 录生命体征 T36.8 P80 BP120/80
6. 录查体"咽部充血，双肺呼吸音清"
7. 录诊断 J06.9 为主诊断
8. 录医嘱"多饮水，3 天复诊"
9. 确认签名

**通过标准**：必填校验逐项生效；过敏三态明确；确认后锁定；版本与 Hash 建立；审计完整。

### S2 一次完整的中医病历（F108 → F109 → F19）
1. 录主诉、现病史
2. 中医四诊：舌质红、苔黄腻、脉弦滑、神色形态
3. 辨证：病名"感冒"、证型"风热犯肺证"、治法"疏风清热"
4. 治法中"针灸辅助"转为处置医嘱
5. 确认签名

**通过标准**：舌脉结构化；病名证型成对；治法必填；四诊可追溯；中医模式校验生效。

### S3 AI 草稿到确认（M04 → F11 → F19）
1. 语音录入 → AI 生成现病史草稿
2. 医生修改其中一段
3. 确认签名
4. 检查：现病史标记 AI_MODIFIED，医生修改部分可区分

**通过标准**：来源标记固化且归档后不可消除；AI 内容未经确认不得直接落业务库。

### S4 确认后修改留痕（F19 → M11 F77）
1. 病历已确认
2. 医生发现主诉有误，走留痕修改
3. 填原因 → 新建版本
4. 检查：原版本完整保留，Hash 链延续，审计含前后值

**通过标准**：原内容未被覆盖；版本链条完整；修改原因已记录。

## 2. 故障场景（本模块专属）

### FA1 书写中崩溃
- 操作：编辑病历各字段过程中强杀进程
- 期望：自动草稿恢复最近内容；已保存部分完整；无脏数据
- 通过标准：草稿可恢复，无半写记录

### FA2 确认过程中崩溃
- 操作：点击确认、事务执行中强杀
- 期望：病历要么 DRAFT 要么 CONFIRMED；若 CONFIRMED 则签名、版本、Hash 全部齐备
- 通过标准：无"已确认但无签名/无版本"的状态

### FA3 过敏史接口失败时的开方降级
- 操作：mock 过敏查询失败后开处方
- 期望：开方环节向"更谨慎"方向降级（提示未采集、要求人工确认），**绝不视为"无过敏"**
- 通过标准：安全方向正确

### FA4 引用检验结果后被更正
- 操作：病历引用了 M05 结果，随后该结果被更正
- 期望：病历提示引用已更新；已确认病历内容不被自动改写
- 通过标准：归档不可变原则成立

### FA5 长文本与并发
- 操作：录入 5000 字现病史并快速连续保存
- 期望：无内容丢失、无重复记录、无卡顿
- 通过标准：内容完整，性能可接受

## 3. 跨模块契约检查

| 检查项 | 期望 |
|---|---|
| 聚合根 | 病历挂在 Visit 下，无脱 Visit 病历 |
| 确认锁定 | CONFIRMED 后不可直接编辑，修改走 F77 |
| AI 来源标记 | 来源标记随确认固化，归档后不可消除 |
| 过敏接口 | `allergy.list()` 被 M02 工作台与 M06 处方规则正确消费 |
| 辅助检查 | 只存引用不复制，源更新有提示 |
| 医嘱边界 | 医嘱不含药品，药品拦截提示生效 |
| 中医校验 | 病名证型成对、舌脉必填（中医模式） |
| 快照 | 归档时患者快照固化 |
