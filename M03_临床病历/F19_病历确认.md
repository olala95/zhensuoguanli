# F19 病历确认

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: M]

> **这是病历生命周期的关键不可逆点。** 确认后内容锁定，修改只能走 M11 F77 留痕修改。

---

## 1. 职责

医生对本次就诊病历做确认签名，锁定内容，使其进入不可变状态并具备归档资格。

---

## 2. 依赖

- 依赖：F10–F18（全部病历内容）、M12（审计）、M11（后续版本管理）
- 被依赖：M11 归档（只有 CONFIRMED 才能归档）、M15 统计、M06（处方已确认的前置）

---

## 3. 涉及的表

`record`、`record_signature`（M03 自有）；`record_version`、`record_hash` 由 M11 写

---

## 4. 规则

**R1 确认前必填校验。**
| 项 | 要求 |
|---|---|
| 主诉 | 必填 |
| 现病史 | 必填 |
| 诊断 | 至少一条（可为"待查"） |
| 中医模式 | 病名 + 证型成对 |
| 过敏史 | 必须处于三态之一（不允许未采集状态确认） |

校验不通过 → 列出缺失项，不允许确认。

**R2 确认即签名。** 记录签名人、签名时间、签名方式（密码确认 / 电子签名）。签名后写入 `record_signature`。

**R3 确认后锁定。** `CONFIRMED` 之后：
- 所有内容字段不可直接编辑
- 修改走 M11 F77（新建版本 + 原因 + 原版本保留）
- Hash 链记录（M11 F80）

**R4 确认前预览。** 确认前展示完整病历预览（含 AI 生成内容的来源标记），医生确认无误后签名。

**R5 AI 内容标记固化。** 确认时把 `source`（AI / AI_MODIFIED / MANUAL）固化到记录中，**归档后不可消除**。这是合规要求：能区分哪些是 AI 生成、哪些是医生确认。

**R6 整份套用模板未修改需提示。** 检测到病历内容与某模板高度一致（未修改）时，提示医生复核后再确认（R-M03-10）。

**R7 处方状态联动。** 确认病历时若存在未确认处方，提示"存在未确认处方"（不强制，因为处方有独立确认流程 F37）。

**R8 确认写高风险审计？否。** 病历确认是正常业务操作，写 `audit_operation` 即可，**不是**高风险操作（高风险是解封、修改留痕）。

**R9 不可取消确认。** 确认后不可回到 DRAFT。

**R10 未确认的病历可删除。** DRAFT 状态且创建者本人可删除（写审计）。

---

## 5. 状态与流程

```
DRAFT
  → 点击确认
  → 必填校验（R1）
      → 不通过：列出缺失项，终止
  → 展示完整预览（含 AI 来源标记）
  → 模板未修改检测（R6）→ 提示复核
  → 医生签名（密码/电子签名）
  → 事务内：置 CONFIRMED + 写 record_signature + 固化 source 标记 + 通知 M11 建版本与 Hash + 写审计
  → 完成，内容锁定
```

---

## 6. 验收标准

**AC1（正常确认）**
- Given 病历内容完整（主诉、现病史、诊断、过敏史三态之一）
- When 医生签名确认
- Then 状态置 CONFIRMED，`record_signature` 记录签名人/时间/方式，M11 建立版本与 Hash，审计完整
- 验证方式：自动

**AC2（必填校验拦截）**
- Given 主诉为空
- When 尝试确认
- Then 拒绝并明确列出"主诉缺失"
- 验证方式：自动

**AC3（过敏未采集拦截）**
- Given 过敏史状态为 NOT_COLLECTED
- When 尝试确认
- Then 拒绝并提示先采集或标记"确认无过敏"
- 验证方式：自动

**AC4（中医模式证型校验）**
- Given 开启中医模式且有病名无证型
- When 尝试确认
- Then 拒绝并提示补证型
- 验证方式：自动

**AC5（AI 来源标记固化）**
- Given 病历中现病史为 AI 生成、主诉为医生修改
- When 确认
- Then 现病史标记 `AI`、主诉标记 `AI_MODIFIED`，**归档后不可消除**
- 验证方式：自动（跨模块，需 M11 配合）

**AC6（确认后锁定）**
- Given 病历已 CONFIRMED
- When 尝试直接编辑主诉
- Then 被拒绝，需走 F77 留痕修改
- 验证方式：自动

**AC7（不可取消确认）**
- Given 已确认
- When 尝试回到 DRAFT
- Then 拒绝
- 验证方式：自动

**AC8（模板未修改提示）**
- Given 病历内容与模板完全一致未修改
- When 确认
- Then 先提示复核，医生确认后方可继续
- 验证方式：自动

**AC9（未确认处方提示）**
- Given 存在未确认处方
- When 确认病历
- Then 提示但不阻断
- 验证方式：自动

**AC10（事务性）**
- Given 确认过程中 M11 建版本失败
- When 执行
- Then 整体回滚，病历保持 DRAFT
- 验证方式：自动（注入失败）

**AC11（崩溃一致性）**
- Given 确认执行中强杀进程
- When 重启
- Then 病历要么 DRAFT 要么 CONFIRMED，无中间态；若 CONFIRMED 则签名与版本记录完整
- 验证方式：自动

## 7. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E2001 | 必填项缺失 | 否 |
| E3019 | 过敏史未采集 | 否 |
| E3023 | 中医病名缺证型 | 否 |
| E3025 | 病历已确认，不可重复确认 | 否 |
| E1010 | 审计写入失败 | 是 |

---

## 8. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 签名验证失败 | 不变更状态，允许重试 |
| M11 版本/Hash 失败 | 整体回滚（AC10） |
| 崩溃 | 事务保证；无"已确认但无签名"的状态 |
