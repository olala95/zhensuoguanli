# F28 检查申请

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: M]

---

## 1. 职责

医生为患者开立外送检验申请单，生成收费明细并进入采样流程。

---

## 2. 依赖

- 依赖：F27（项目目录）、M02（Visit 上下文）、**M09（收费）**、M12
- 被依赖：F29（采样条码）、F117（送检）、M03（F16 引用）

---

## 3. 涉及的表

`lab_order`（M05 自有）
**写入 M09 账单通过接口**（`bill.addItem()`）

---

## 4. 规则

**R1 申请单挂 Visit。** 不可脱离 Visit 开单。

**R2 开单即生成收费明细。** 选中项目后，通过 M09 接口向该 Visit 的账单添加明细行（按**开单时的收费价**）。**不重复收费**：同一申请单不重复添加。

**R3 未收费不可采样/送检。** 申请单状态 `ORDERED`（已开单）后需完成收费才能推进到 `SAMPLED`。系统校验账单支付状态。

**R4 支持多项目一单。** 一次申请可含多个外送项目（可能分属不同机构），机构不同时在送检登记（F117）中分开处理。

**R5 标本要求展示。** 开单时展示各项目的标本要求（空腹、晨尿等），便于医生告知患者。

**R6 申请单可取消（未送检前）。** `ORDERED` 或 `SAMPLED` 状态可取消 → 触发 M09 退款；`DELIVERED` 之后不可取消。

**R7 急检标记。** 可标记急检（加急），送检列表中优先显示。

**R8 临床信息随单。** 申请单可填写临床诊断与备注，随标本送检（打印在送检单上，M10）。

**R9 改价需权限。** 申请单金额默认取项目价，改价需相应权限并写 `audit_high_risk`。

**R10 患者快照。** 申请单保存患者姓名/性别/年龄快照（送检单打印与归档需要）。

---

## 5. 状态与流程

```
选择 Visit → 选项目（可多项目）
  → 展示标本要求
  → 生成申请单（DRAFT → ORDERED）
  → 通过 M09 接口添加账单明细
  → 收费完成 → 可采样（SAMPLED）
  → 进入 F117 送检
```

---

## 6. 验收标准

**AC1（开单成功）**
- Given 选择"血常规"（30 元）
- When 开单
- Then 申请单生成，状态 ORDERED，账单中新增一行 30 元明细
- 验证方式：自动（跨模块，需 M09 配合）

**AC2（不重复收费）**
- Given 同一申请单重复提交
- When 检查账单
- Then 只有一行明细（幂等）
- 验证方式：自动

**AC3（未收费不可采样）**
- Given 申请单已开单但未收费
- When 尝试标记采样
- Then 拒绝并提示先收费
- 验证方式：自动

**AC4（多项目多机构）**
- Given 选择 A 机构的血常规与 B 机构的尿常规
- When 开单
- Then 一单含两项目；F117 送检时按机构分开登记
- 验证方式：自动（跨模块，需 F117 配合）

**AC5（取消触发退款）**
- Given 申请单已收费未送检
- When 取消
- Then 申请单 CANCELLED，触发 M09 退款流程
- 验证方式：自动（跨模块，需 M09 配合）

**AC6（已送检不可取消）**
- Given 申请单已 DELIVERED
- When 尝试取消
- Then 拒绝
- 验证方式：自动

**AC7（标本要求展示）**
- Given 项目标注"需空腹"
- When 开单
- Then 界面提示需空腹
- 验证方式：自动

**AC8（改价审计）**
- Given 修改申请单金额
- When 保存
- Then 写 `audit_high_risk`；无权限者被拒绝
- 验证方式：自动

**AC9（患者快照）**
- Given 开单时患者姓名"张三"
- When 之后患者改名
- Then 申请单中快照仍为"张三"
- 验证方式：自动

**AC10（Visit 作废联动）**
- Given Visit 被作废（M02 F125）
- When 该 Visit 下有未送检申请单
- Then 申请单被取消（通过 `voidByVisit` 接口）
- 验证方式：自动（跨模块）

**AC11（崩溃一致性）**
- Given 开单执行中强杀
- When 重启
- Then 申请单与账单明细要么都在要么都不在
- 验证方式：自动

---

## 7. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E2001 | 必填缺失 | 否 |
| E3026 | 未收费不可采样 | 否 |
| E3027 | 已送检不可取消 | 否 |
| E6002 | 无改价权限 | 否 |
| E1010 | 审计写入失败 | 是 |

---

## 8. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 账单接口失败 | 整体回滚，申请单不创建 |
| 崩溃 | 事务保证申请单与账单明细一致 |
| M09 不可用 | 拒绝开单并提示（不允许创建无法收费的申请单） |

---

## 9. 契约缺口

- 需 M09 提供 `bill.addItem(visitId, item)` 与 `bill.isPaid(visitId)` 接口，契约在 M09 开发时冻结（但 M05 在第二阶段、M09 在第三阶段，**需提前约定接口签名**）。
