# M12 安全审计

> 阶段：第一阶段（紧随 M14）
> 依赖：M14（用户会话上下文、配置）
> 被依赖：**全部模块**（每个写操作都要调用本模块的审计接口）

---

## 1. 模块职责

记录系统中一切可追溯的操作痕迹：操作审计、数据修改审计（含前后值）、高风险操作、登录审计、时间异常、权限拒绝。

**本模块是合规底座，不是日志。** 审计数据用于回答"谁在什么时候对什么业务做了什么、改前是什么、改后是什么"。

---

## 2. 为什么必须在第一阶段

审计是**横切关注点**。若等系统写完再补，意味着要回到每一张表、每一次写操作重新加埋点——那时代价极大且容易遗漏。

**原则：审计埋点必须与第一张业务表同时诞生。** 第二阶段开始后，任何新增业务表若缺审计埋点，视为未完成。

---

## 3. 表所有权（详见 `04_DATA_MODEL`）

| 表 | 职责 | 特性 |
|---|---|---|
| `audit_operation` | 操作审计（F84） | **只 INSERT** |
| `audit_data_change` | 数据修改审计，含 before/after（F85） | **只 INSERT** |
| `audit_high_risk` | 高风险操作（F86） | **只 INSERT** |
| `audit_login` | 登录/锁屏/解锁/登出/角色切换（F87） | **只 INSERT** |
| `audit_time_anomaly` | 系统时间异常（F88） | **只 INSERT** |
| `audit_permission` | 权限拒绝（F89） | **只 INSERT** |

> `audit_login` 虽由 M14 的登录流程触发，但表归 **M12**（审计性质），M14 通过本模块接口写入。

---

## 4. 模块级规则

**R-M12-1 只追加，永不修改。** 6 张审计表**只允许 INSERT**，禁止 UPDATE / DELETE（含软删除）。应用层拦截 + 数据库触发器双重保证。**任何形式的删除尝试写 `audit_high_risk` 并告警。**

**R-M12-2 时间取系统时间。** 审计时间一律由本模块取系统时间生成，**不接受调用方传入的时间**。调用方可传业务发生时间（如 `occurred_at`），但审计记录自身的 `audited_at` 必须是系统时间。

**R-M12-3 审计失败必须阻断业务。** 若审计写入失败，**业务事务整体回滚**。宁可操作失败，不可留下无审计的操作。这是本模块最重要的规则。

**R-M12-4 审计在同一事务内。** 业务写入与审计写入必须在**同一个数据库事务**中，保证"要么都有要么都没有"。

**R-M12-5 before/after 必须完整。** 数据修改审计必须记录：表名、记录 ID、字段名、修改前值、修改后值。禁止只记"某字段被修改"。

**R-M12-6 敏感值脱敏策略。** 密码、AI 密钥等不进审计；身份证号在审计中记录**后 4 位 + 哈希**，不记完整号码。病历内容变更记字段级前后值（合规需要），但导出诊断包时脱敏（F104）。

**R-M12-7 必填上下文。** 每条审计必须含：操作人 ID、角色、模块、功能点编号、时间、结果（成功/失败）、来源（UI / AI / Hardware / IPC）。

**R-M12-8 审计表本身的性能。** 审计写入量大，必须走批量/异步落盘以外的同步事务写入（R3 要求同步）。索引按 `时间 + 模块 + 操作人` 建，支持快速检索。

**R-M12-9 来源必须标记。** AI 产生的操作（如 AI 草稿落库、AI 建议采纳）来源标记为 `AI`，且必须同时记录确认人（医生），以便区分"AI 生成"与"医生确认"。

---

## 5. 状态机引用

本模块无状态机。审计记录一旦写入即终态。

---

## 6. 对外接口（供其他模块调用）

| 接口 | 说明 | 调用方 |
|---|---|---|
| `audit.operation(ctx, action, target)` | 操作审计 | 全部 |
| `audit.dataChange(ctx, table, recordId, field, before, after)` | 字段级变更 | 全部 |
| `audit.highRisk(ctx, type, detail)` | 高风险操作 | M06/M09/M11/M13/M14 |
| `audit.login(ctx, event)` | 登录类事件 | M14 |
| `audit.timeAnomaly(detail)` | 时间异常 | M14/全局检测 |
| `audit.permission(ctx, permission)` | 权限拒绝 | M14 |

**所有接口必须在数据库事务内调用**（R-M12-4）。

---

## 7. 高风险操作清单（F86）

以下操作一律写 `audit_high_risk`：

| 类别 | 操作 |
|---|---|
| 作废 | 就诊作废、处方作废、账单作废、检验申请作废 |
| 删除 | 任何软删除业务主记录 |
| 退款 | 退款、退药退款、红字冲正 |
| 病历 | 病理解封、病历修改（留痕）、导出 |
| 权限 | 用户角色变更、密码重置、权限配置变更 |
| 配置 | 敏感配置变更、关闭自动备份/锁屏 |
| 数据 | 数据恢复、手动备份删除、患者合并 |
| 异常 | 审计表删除尝试、时间异常、连续登录失败（≥3 次） |
