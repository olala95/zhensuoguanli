# F86 高风险操作审计

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: M]

---

## 1. 职责

对作废、删除、退款、冲正、解封、权限变更、数据恢复等高风险动作做**强化记录**，并在部分场景下要求二次确认与原因填写。

---

## 2. 依赖

- 依赖：M14（用户上下文）、F84/F85（基础审计）
- 被依赖：M02、M06、M09、M11、M13、M14

---

## 3. 涉及的表

`audit_high_risk`（M12 自有，**只允许 INSERT**）

---

## 4. 规则

**R1 高风险清单**（见 MODULE.md §7）为本功能的记录范围。**清单外的操作不得写入本表**，避免稀释。

完整的八类：作废 / 删除 / 退款冲正 / 病历解封与修改导出 / 权限变更 / 敏感配置变更 / 数据恢复与患者合并 / 异常（审计删除尝试、时间异常、连续登录失败）。

**R2 强制原因。** 以下操作**必须填写原因**才能执行：就诊作废、处方作废、账单作废、退款、红字冲正、病历解封、患者合并、数据恢复。原因不填 → 拒绝。

**R3 二次确认。** 以下操作弹二次确认并明确告知后果：数据恢复（覆盖现有数据）、患者合并（不可逆）、病历解封、关闭自动备份、关闭锁屏。

**R4 记录内容。** 类型、目标对象（类型+ID+单号）、原因、操作人、角色、时间、结果、关联 `audit_operation.id`、影响范围描述（如"影响 3 张单据"）。

**R5 失败也记录。** 高风险操作的**尝试**（即使失败）也要记录，包括被拒绝的删除尝试。

**R6 告警联动。** 以下情况触发界面告警条：审计表删除尝试、连续登录失败 ≥3 次、时间异常、数据恢复执行、自动备份连续失败。

**R7 不可修改删除。** 同 F84 R4。

**R8 高风险不等于禁止。** 本功能只做记录与确认，**不替代业务规则判断**（如"已发药处方不可作废"由 M06 判定）。

**R9 每日汇总。** 提供"今日高风险操作"视图，供管理员复核。

## 5. 验收标准

**AC1（作废记录）**
- Given 医生作废一张未发药处方
- When 填写原因"患者要求取消"并提交
- Then `audit_high_risk` 新增一条：type=处方作废、目标单号、原因、操作人、角色、时间；同时有对应 `audit_operation`
- 验证方式：自动

**AC2（原因必填）**
- Given 作废一张账单
- When 不填原因直接提交
- Then 拒绝执行，返回 `E2001`，账单状态不变
- 验证方式：自动

**AC3（二次确认）**
- Given 执行数据恢复（将覆盖现有数据）
- When 触发操作
- Then 弹出二次确认，明确告知"将覆盖现有数据且不可撤销"；取消则不执行
- 验证方式：自动

**AC4（失败尝试也记录）**
- Given 尝试删除一张已发药处方（业务规则拒绝）
- When 操作被拒
- Then `audit_high_risk` 仍记录该尝试，result=failure，error_code 正确
- 验证方式：自动

**AC5（审计删除尝试告警）**
- Given 有人尝试 DELETE 审计表
- When 操作被拦截
- Then 写 `audit_high_risk`，界面弹出告警条，记录尝试者与时间
- 验证方式：自动

**AC6（权限变更记录）**
- Given 管理员给用户增加"收费员"角色
- When 提交
- Then 记录含 before 角色集合、after 角色集合、操作人
- 验证方式：自动

**AC7（敏感配置变更）**
- Given 管理员关闭自动备份
- When 提交
- Then 二次确认 + 记录 `audit_high_risk`（含 before/after 值）
- 验证方式：自动

**AC8（患者合并记录）**
- Given 合并两名重复患者
- When 提交
- Then 记录合并双方 ID、被影响的就诊/处方数量、操作人、原因；合并不可逆且明确提示
- 验证方式：自动（跨模块，需 M01 配合）

**AC9（今日汇总）**
- Given 当日发生 5 次高风险操作
- When 管理员打开"今日高风险操作"
- Then 完整列出 5 条，可按类型筛选
- 验证方式：自动

**AC10（不可修改）**
- Given 已存在高风险记录
- When 尝试 UPDATE/DELETE
- Then 拒绝并写新的 `audit_high_risk`
- 验证方式：自动

## 6. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E1010 | 审计写入失败 | 是 |
| E1011 | 尝试修改审计记录 | 否 |
| E2001 | 原因必填缺失 | 否 |
| E6002 | 无权限执行高风险操作 | 否 |

---

## 7. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 高风险审计写入失败 | 业务整体回滚（不允许高风险操作无审计） |
| 二次确认被跳过（异常路径） | 服务端必须独立校验"已确认"标记，不信任前端 |
| 告警未送达 | 记录仍存在；界面下次打开时补显示未确认告警 |
