# M12 安全审计 — 模块验收

> 本文件**只写跨 F 的端到端场景与本模块的故障场景**，不重复各 `Fxx.md` 内的 AC。

---

## 1. 端到端场景

### S1 一次完整业务操作的审计链条（M14 → M12 → M01/M02）
1. 医生 A 登录（角色：医生）
2. 建档患者 P
3. 创建 Visit
4. 写病历并确认
5. 切换角色为收费员后收费
6. 登出

**通过标准**：
- 每一步都有 `audit_operation`，且角色字段随会话切换正确变化
- 患者建档、病历内容的字段级变更有 `audit_data_change`
- 登录/切换/登出有 `audit_login`
- 任意一步的"谁、何时、从什么值改到什么值"均可完整还原

### S2 高风险操作的完整留痕（M12 → M06/M09）
1. 医生开方并确认
2. 医生作废该处方（填原因）
3. 收费员执行一次退款
4. 管理员执行数据恢复

**通过标准**：四类动作均写 `audit_high_risk`，含原因/前后值/影响范围；退款与恢复有二次确认记录；无原因的作废被拒绝。

### S3 权限边界的留痕（M14 → M12）
1. 医生尝试收费 → 被拒
2. 医生尝试修改已确认病历 → 被拒
3. 管理员尝试给自己加角色 → 被拒

**通过标准**：三条 `audit_permission` 记录完整；越权修改已确认病历与自我提权升级为 `audit_high_risk`。

## 2. 故障场景（本模块专属）

### FA1 审计写入失败 → 业务阻断
- 操作：模拟 `audit_operation` 写入失败后执行一笔收费
- 期望：收费事务整体回滚，无账单、无支付记录，返回 `E1010`
- 通过标准：**绝不允许出现无审计的业务数据**

### FA2 审计表删除尝试
- 操作：直接对 6 张审计表执行 DELETE / UPDATE
- 期望：触发器与应用层双重拦截；写 `audit_high_risk`；界面告警
- 通过标准：审计数据零丢失，尝试有记录

### FA3 系统时间回拨
- 操作：将系统时间回拨一天后启动并做若干业务操作
- 期望：F88 记录异常；编号不重复；审计时间不倒流；业务状态不倒流
- 通过标准：编号唯一性成立，无倒序审计

### FA4 审计写入中途崩溃
- 操作：业务操作（含审计写入）执行中强杀进程
- 期望：业务与审计要么都在要么都不在（同事务）
- 通过标准：不存在"有业务无审计"或"有审计无业务"

### FA5 审计表膨胀
- 操作：连续产生 10 万条审计记录
- 期望：写入性能无明显衰减；查询按索引仍可用；无自动删除
- 通过标准：关键查询（按时间+操作人）响应 < 1 秒

## 3. 审计覆盖自检（阶段门禁必跑）

提供工具扫描全部业务表，输出两类清单：

- **缺失清单**：存在写操作但无审计埋点的表
- **可疑清单**：有审计埋点但审计与业务不在同一事务的表

**门禁标准**：第一阶段结束时"缺失清单"必须为空；任何阶段新增业务表后重跑，仍须为空。

## 4. 跨模块契约检查

| 检查项 | 期望 |
|---|---|
| 审计接口统一 | 全部模块走 `audit.*` 接口，无模块直接 INSERT 审计表 |
| 同事务 | 业务写入与审计写入在同一事务 |
| 时间来源 | `audited_at` 一律系统时间，无模块传入 |
| 敏感脱敏 | 密码/密钥零记录；身份证仅后 4 位 + 哈希 |
| AI 来源 | 来源为 AI 的操作必带 `ai_confirmed_by` |
| 表只读性 | 6 张审计表触发器均已安装且生效 |
| 日志 vs 审计 | 无"审计只写日志不入库"的情况 |
