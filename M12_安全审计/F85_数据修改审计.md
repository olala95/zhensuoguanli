# F85 数据修改审计

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: M]

---

## 1. 职责

记录**字段级**的数据变更：哪张表、哪条记录、哪个字段、改前值、改后值、谁改的、为什么改。

与 F84 的区别：F84 记录"做了什么操作"，F85 记录"数据变成了什么样"。

---

## 2. 依赖

- 依赖：M14（用户上下文）、F84（操作审计先写，本功能在其事务内追加）
- 被依赖：全部模块（尤其是 M03 病历、M06 处方、M09 账单、M07 库存）

---

## 3. 涉及的表

`audit_data_change`（M12 自有，**只允许 INSERT**）

---

## 4. 规则

**R1 必记字段。** 表名、记录 ID、字段名、`before`、`after`、`operator_id`、`operator_role`、`module`/`feature`、`reason`（修改原因，病历修改强制）、`audited_at`（系统时间）、关联的 `audit_operation.id`。

**R2 只记实际变化的字段。** 值未变化的字段不记录，避免审计表膨胀。

**R3 多行变更逐行记。** 一次操作修改 N 条记录的 M 个字段 → 记录 N×M 条（仅实际变化）。批量操作可汇总，但**业务单据级必须明细**。

**R4 before 必须取自变更前。** 必须在 UPDATE 执行前读取原值，禁止用"新值推断旧值"。

**R5 病历修改强制填原因。** M03/M11 相关的病历内容变更，`reason` 为必填；无原因拒绝修改（走 F77 留痕修改）。

**R6 大字段处理。** 病历正文等长文本：记录字段级前后值（合规需要），但**超长内容**（> 10KB）记录摘要 + 内容哈希，原文通过版本表（M11 `record_version`）追溯。

**R7 敏感字段脱敏。** 密码、密钥字段**禁止**进审计（连 before/after 哈希都不记）；身份证记后 4 位 + 哈希。

**R8 审计失败阻断业务。** 同 F84 R2：写入失败 → 业务事务整体回滚。

**R9 禁止修改删除。** 同 F84 R4。

**R10 已确认单据的修改走留痕路径。** 已确认的病历/处方/账单修改，除记录本审计外，必须走对应模块的留痕机制（M11 F77 / M09 F62 红冲），**不得直接改原记录**。

## 5. 验收标准

**AC1（字段级记录）**
- Given 处方 R202610090012 中某药品数量从 2 盒改为 3 盒
- When 修改完成
- Then `audit_data_change` 新增一条：table=prescription_item、record_id=该明细、field=quantity、before=2、after=3、操作人、时间
- 验证方式：自动

**AC2（只记变化字段）**
- Given 一次修改提交了 5 个字段，其中 3 个值未变
- When 修改完成
- Then 只产生 2 条变更记录
- 验证方式：自动

**AC3（before 取自变更前）**
- Given 药品库存数量为 100
- When 发药扣减 20
- Then 审计中 before=100、after=80，且 before 值为 UPDATE 执行前真实读取
- 验证方式：自动

**AC4（多行变更）**
- Given 一次盘点调整了 5 个批次的库存
- When 提交
- Then 产生 5 条（或 5×字段数）变更记录，逐条对应批次
- 验证方式：自动

**AC5（病历修改强制原因）**
- Given 已确认的病历
- When 尝试修改主诉但**不填**修改原因
- Then 拒绝修改，返回 `E2001`，无业务变更
- 验证方式：自动

**AC6（已确认病历不被直接改写）**
- Given 已确认病历 M
- When 执行留痕修改（F77）
- Then 原版本完整保留，新建版本；`audit_data_change` 记录变更；原始记录内容未被覆盖
- 验证方式：自动（跨模块，需 M11 配合）

**AC7（敏感字段不入库）**
- Given 修改用户密码
- When 检查 `audit_data_change`
- Then 不存在 password 字段的任何记录（连哈希都没有）
- 验证方式：自动

**AC8（审计失败阻断）**
- Given 模拟 `audit_data_change` 写入失败
- When 执行一次库存调整
- Then 库存事务整体回滚，数量不变
- 验证方式：自动

**AC9（可追溯性）**
- Given 任意一个业务字段当前值
- When 查询该字段的变更历史
- Then 能完整还原变更链条：谁、何时、从什么值改到什么值、在哪次操作中
- 验证方式：自动

**AC10（不可修改）**
- Given 已存在变更记录
- When 尝试 UPDATE/DELETE
- Then 拒绝并写 `audit_high_risk`
- 验证方式：自动

## 6. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E1010 | 审计写入失败 | 是 |
| E1011 | 尝试修改审计记录 | 否 |
| E2001 | 修改原因必填缺失 | 否 |
| E3005 | 已确认单据不允许直接修改 | 否（需走留痕路径） |

---

## 7. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 审计写入失败 | 业务回滚；重试业务操作 |
| before 读取失败 | 视为操作失败，不执行 UPDATE |
| 长文本截断 | 记录摘要 + 哈希，原文由版本表追溯；不因截断失败 |
