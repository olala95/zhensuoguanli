## 1. 端到端场景

### S1 报表口径与手工核对一致（第四阶段门禁核心）

```
建档 → 就诊 → 开方（成药+饮片）→ 处置 → 收费 → 发药 → 退药退款 → 日结
   → 用同一批数据分别跑：F119 日营收 / F120 门诊量 / F121 进销存 / F122 处方统计
   → 与逐步手工核对结果比对
```

**判定**：
- [ ] 营收 = Σ 成功收款 − Σ 成功退款，且按 `paid_at` 归集
- [ ] 门诊量只含 `COMPLETED`，与 Visit 列表人工点数一致
- [ ] 客单价 = 营收 ÷ 门诊量，与手算一致（门诊量为 0 时返回 null）
- [ ] 进销存六段式平衡：期末 = 期初 + 入库 − 出库 + 退药 − 报损 ± 盘点
- [ ] 处方统计只含有效状态，作废单列

### S2 只读边界

```
任意报表接口 × N 次 → 审计条数不变 → 业务表无新增行
```

**判定**：
- [ ] 报表查询不写 `audit_operation`（审计只记写操作）
- [ ] 报表代码里不存在对非 `v_` 视图的查询（R-M15-1）
- [ ] 导出才写 `audit_high_risk`，查询不写

### S3 权限与数据外流

```
医生角色查看报表 → 允许（若授予 report.view）
医生角色导出报表 → 拒绝 E6002 + audit_permission
管理员导出 → 成功 + audit_high_risk
```

**判定**：
- [ ] 越权一律拒绝并留痕，不静默放行
- [ ] 导出文件带口径说明，离手后仍可复核

### S4 全链路闭环（第四阶段门禁）

```
建档 → 就诊 → 病历（中医）→ 开方（中药）→ 收费 → 发药 → 日结 → 报表
```

**判定**：
- [ ] 报表中药饮片的出库量 = 剂量 × 付数（与 M07 F114 一致）
- [ ] 代煎费与包装费计入处方金额与营收
- [ ] 日结单的净收与 F119 当日营收一致（同源不同粒度）

## 2. 故障演练

| # | 场景 | 期望 |
|---|---|---|
| M15-1 | 视图未创建时查询报表 | 明确提示"请执行迁移"，**不静默降级查原始表** |
| M15-2 | 传入超过 366 天的区间 | 拒绝 E3080，不发起全表扫描 |
| M15-3 | 导出时磁盘写失败 | 抛 E1002，不留下半截 CSV |
| M15-4 | 无 report.export 权限导出 | 拒绝 E6002 并写 `audit_permission` |
| M15-5 | 流水与库存不一致时查进销存 | 以流水为准并标注差异，提示走盘点校正 |
| M15-6 | 医生账号被软删后查工作量 | 仍能显示（用快照名），不丢行 |
