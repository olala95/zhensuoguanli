# F119 日营收与班结报表

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: M]

---

## 1. 职责

按营业日（或班次）给出营收全貌：应收、实收、退款、净营收、分渠道收款、笔数、客单价、未结账笔数。

---

## 2. 依赖

- 依赖：`v_revenue_daily` 视图（payment + refund + bill）、M09 已埋的 `paid_at`
- 被依赖：UI 报表首页、F124 导出

---

## 3. 涉及的表

只读：`v_revenue_daily`；写入：无（`report_snapshot` 可选缓存）

---

## 4. 规则

**R1 营收口径（契约 §7）。**
```
营收 = Σ payment.amount_fen (status='SUCCESS') − Σ refund.total_amount_fen (status='SUCCEEDED')
```
视图以**正数记收款、负数记退款**，报表只需 SUM(amount_fen)。

**R2 归集时间 = `payment.paid_at`**，不是 Visit 创建时间、不是账单生成时间（契约 §7）。退款按 `refund.occurred_at` 归集。

**R3 渠道分项。** 按 `channel` 分组（现金/微信/支付宝/银行卡/其他），同时给出笔数；分渠道之和 = 实收。

**R4 应收 vs 实收。** 应收取该区间账单 `total_amount_fen` 之和；实收取支付成功额。两者不等时**不静默抹平**，同时展示并标注差额（常见于未收费或部分退款）。

**R5 客单价 = 营收 ÷ 门诊量**，门诊量口径同 F120（仅 `COMPLETED`）。门诊量为 0 时客单价返回 `null` 而非 0（避免误导）。

**R6 未结账提示。** 统计区间内 `PENDING` 账单的笔数与金额，单独列示（不是营收的一部分）。

**R7 班结。** 同一天可多次日结；若传入 `settlement_id`，则只汇总该日结单范围内的账单（与 M09 F64 增量日结对齐）。

**R8 金额整数分 + 展示串。** 返回 `*_fen` 与 `*_yuan`（字符串，2 位小数），UI 不自行换算（R-M15-4）。

**R9 区间左闭右开。** `from <= date < to+1日`，避免边界重复计。

## 5. 验收标准

**AC1（净营收 = 收款 − 退款）**
- Given 当日收款 10000 分、退款 2000 分
- When 查日营收
- Then 净营收 8000 分
- 验证方式：自动

**AC2（按 paid_at 归集）**
- Given 一笔昨天开的账单今天收款
- When 查今天的日营收
- Then 计入今天
- 验证方式：自动

**AC3（渠道分项之和 = 实收）**
- Given 现金 3000 + 微信 7000
- When 查渠道分项
- Then 分项合计 10000，笔数正确
- 验证方式：自动

**AC4（客单价）**
- Given 营收 8000、门诊量 4
- When 查客单价
- Then 2000 分
- 验证方式：自动

**AC5（门诊量为 0 时客单价为 null）**
- Given 区间内无已完成就诊
- When 查客单价
- Then 返回 null，不返回 0
- 验证方式：自动

**AC6（未结账单独列示）**
- Given 有 2 张 PENDING 账单共 5000 分
- When 查日营收
- Then `pending_count=2`、`pending_amount_fen=5000`，且不计入营收
- 验证方式：自动

**AC7（区间边界不重复）**
- Given 查询 10-01～10-02 与 10-02～10-03
- When 两段相加
- Then 10-02 只被计入一次
- 验证方式：自动

**AC8（只读不写审计）**
- Given 连续查询 10 次
- When 对比 `audit_operation` 条数
- Then 无新增
- 验证方式：自动

**AC9（口径可复核）**
- Given 任意一次查询
- When 看返回
- Then 含 `criteria`（区间、口径说明、生成时间）
- 验证方式：自动
