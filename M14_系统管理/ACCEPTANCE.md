## 1. 端到端场景

### S1 全新机器首次上线（F99 → F102 → F100 → F101）
1. 在一台干净机器安装并启动
2. 初始化向导完成：数据库创建、字典灌入、目录建立、管理员创建
3. 自检 7 项通过
4. 管理员登录 → 创建医生/药师/收费员账号
5. 以收费员登录 → 尝试开处方 → 被拒绝（`E6002`）
6. 以医生登录 → 可开处方
7. 配置诊所名称 → 打印抬头生效

**通过标准**：全流程无阻断；权限边界正确；配置生效；每一步都有审计记录。

### S2 基础数据就绪（F128 → M06/M07/M09 可用性）
1. 下载药品模板 → 填入 100 条 → 导入
2. 下载饮片模板 → 填入 300 条 → 导入
3. 下载收费项目模板 → 填入 200 条 → 导入
4. 重复导入同一批文件一次 → 记录数不增加（幂等）
5. 在药品搜索、饮片选择、账单明细中均可查到这些数据

**通过标准**：M06/M07/M09 具备可测试的数据基础；重复导入无脏数据。

### S3 一天的开始与结束（F100 → F105 → F107）
1. 早上启动 → 自检通过 → 登录 → 检查昨日备份存在
2. 全天业务操作（由其他模块产生）
3. 下班执行退出：列出未完成任务 → 处理 → 触发退出备份 → 优雅关闭

**通过标准**：退出不丢数据；退出备份可用；次日启动自检通过。

## 2. 故障场景（本模块专属）

### FA1 启动时数据库损坏
- 操作：人为损坏数据库文件后启动
- 期望：进入安全模式，业务写入被拒绝，界面引导至诊断（F104）与备份恢复（F93）
- 通过标准：**不允许带着损坏库继续业务操作**

### FA2 初始化中途断电
- 操作：初始化执行到一半断电
- 期望：重启后不残留半成品数据库；可重新初始化；已创建目录保留不报错
- 通过标准：重新初始化成功且自检通过

### FA3 导入中崩溃
- 操作：导入 5000 行数据到一半强杀进程
- 期望：无半导入数据；`sys_import_job` 标记失败；重新导入成功
- 通过标准：数据库校验和与导入前一致

### FA4 磁盘写满
- 操作：模拟磁盘写满后执行配置修改 + 日志写入 + 备份
- 期望：三者均给出明确 `E1002`，业务主流程不被静默破坏；清理后可恢复
- 通过标准：无静默失败，无数据丢失

### FA5 系统时间被回拨
- 操作：将系统时间回拨一天后启动并登录
- 期望：F88 检测到并写 `audit_time_anomaly`；会话与业务时间不倒流；编号序列不混乱（不产生重复编号）
- 通过标准：编号仍唯一；异常有记录

### FA6 强制退出
- 操作：业务进行中强杀进程
- 期望：重启走崩溃恢复；无未提交事务残留；跨表一致性校验通过
- 通过标准：与 S3 后的数据状态一致（除未提交部分）

## 3. 跨模块契约检查

| 检查项 | 期望 |
|---|---|
| 审计归属 | 本模块**不直接写** `audit_login` / `audit_high_risk` 表，一律走 M12 接口 |
| 编号服务 | 全部编号来自 `sys_sequence`，无模块自行生成 |
| 配置唯一来源 | 代码中无硬编码的可调参数（尤其是金额、超时、阈值） |
| 权限入口 | 全部权限判断走 `auth.require()`，无模块自行判断角色名 |
| 跨模块写表 | 仅 F128 通过对方 `import.upsert()` 接口写入，其余零跨模块写表 |
| 单写者 | 本模块不打开额外的写连接；子进程不直接连库 |
