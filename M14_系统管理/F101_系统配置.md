# F101 系统配置

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: M]

## 1. 职责

以键值对形式集中管理全部可调参数，提供读取服务（带缓存）、修改界面（带审计）、默认值与重置能力。

- 被依赖：全部模块

## 3. 涉及的表

`sys_config`（M14 自有）

---

## 4. 规则

**R1 配置唯一来源。** 任何可调参数一律存 `sys_config`。**禁止硬编码**以下类参数：诊所名称与地址、默认付数、代煎费、拆零规则、锁屏超时、自动备份时间、备份保留天数、打印模板选择、各类重试次数与超时、库存预警阈值、AI 超时与重试。

**R2 类型化存储。** `sys_config` 含 `value_type`（string / int / bool / json / money）。读取时按类型转换，类型不匹配抛 `E2002`。金额类配置存**整数分**。

**R3 修改必审计。** 任何 `config.set` 写 `audit_high_risk`，记录 key、before、after、操作人、时间。

**R4 敏感配置限管理员。** 标记为 `sensitive=1` 的配置项（备份路径、AI 接口地址与密钥、硬件端口）仅管理员可改；非管理员尝试 → `E6002` + `audit_permission`。

**R5 缓存与失效。** 配置服务进程内缓存；`config.set` 成功后广播失效通知，订阅方刷新。禁止各模块自行长期缓存配置副本。

**R6 校验前置。** 修改配置时先校验合法性与取值范围（如锁屏超时 1–120 分钟、备份保留 1–3650 天），不合法拒绝并说明原因，不写入。

**R7 关键配置变更需二次确认。** 修改备份路径、AI 接口、数据库连接相关配置时弹二次确认，并提示影响范围。

**R8 重置保留审计。** 恢复默认值操作本身写 `audit_high_risk`，且**不删除**历史配置变更审计记录。

## 6. 验收标准

**AC1（读取与缓存）**
- Given `tcm.default_doses` = 7
- When 调用 `config.get('tcm.default_doses')`
- Then 返回整数 7；同一进程内第二次读取走缓存（不查库）
- 验证方式：自动

**AC2（修改审计）**
- Given 管理员已登录
- When 将 `tcm.default_doses` 从 7 改为 10
- Then `sys_config` 值为 10，`audit_high_risk` 中有一条记录含 before=7、after=10、操作人、时间；缓存已失效，再次读取返回 10
- 验证方式：自动

**AC3（类型校验）**
- Given `security.lock_timeout_min` 为 int 型
- When 尝试写入字符串 "abc"
- Then 拒绝并返回 `E2002`，`sys_config` 值不变，无审计脏记录
- 验证方式：自动

**AC4（范围校验）**
- Given `security.lock_timeout_min` 合法范围 1–120
- When 写入 0 或 999
- Then 拒绝并提示合法范围，值不变
- 验证方式：自动

**AC5（敏感配置权限）**
- Given 当前角色为"医生"
- When 尝试修改 `ai.api_endpoint`（sensitive）
- Then 返回 `E6002`，写入 `audit_permission`，配置值不变
- 验证方式：自动

**AC6（金额配置为整数分）**
- Given `tcm.decoct_fee` 设为 5.00 元
- When 存库后读取原始值
- Then 库中为整数 500（分），显示为 5.00 元
- 验证方式：自动

**AC7（重置默认值保留审计）**
- Given 存在多条配置变更审计记录
- When 执行"恢复默认"
- Then 配置回到默认值，新增一条 `audit_high_risk` 重置记录，**历史审计记录一条不少**
- 验证方式：自动

**AC8（崩溃一致性）**
- Given 修改配置的写操作执行中
- When 强制 kill 进程
- Then 重启后配置要么是旧值要么是新值（事务保证），不存在半写状态；审计记录与最终值一致
- 验证方式：自动（kill 注入）

## 7. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E2001 | 必填配置缺失 | 否 |
| E2002 | 配置类型不匹配 | 否 |
| E2003 | 配置值超出合法范围 | 否 |
| E6002 | 无权限修改敏感配置 | 否 |

---

## 8. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 配置写入中途崩溃 | 事务回滚；重启后读取库中值，缓存重建 |
| 缓存失效通知丢失 | 配置服务提供强制刷新接口；各模块在关键操作前可调用 `config.reload()` |
| 配置文件/表损坏 | 启动自检发现后进入安全模式，允许管理员恢复备份 |
