# F106 系统更新

[TYPE: FEATURE] [PRIORITY: P1] [SIZE: M]

---

## 1. 职责

应用版本检查、更新包下载与校验、数据库迁移执行、更新失败回滚。

---

## 2. 依赖

- 依赖：F99（迁移机制）、M13（**更新前强制全量备份**）、F103（更新日志）
- 被依赖：无

---

## 3. 涉及的表

`sys_migration`、`sys_config`（M14 自有）

---

## 4. 规则

**R1 更新前强制全量备份。** 任何更新动作执行前必须先完成一次全量备份并校验通过。备份失败 → 中止更新。

**R2 离线可用优先。** 核心流程离线可用是硬要求。更新检查失败、下载失败一律**静默降级**（记录日志 + 状态提示），绝不阻塞启动与业务使用。禁止"强制更新才能用"。

**R3 校验签名与校验和。** 更新包必须校验数字签名或 SHA-256 校验和，不通过则拒绝安装并告警。

**R4 迁移只增不改。** 数据库变更一律通过新增迁移脚本完成（`04_DATA_MODEL` §5）。已执行脚本禁止修改。

**R5 更新窗口。** 更新必须在无业务操作进行时执行：检查是否存在未确认处方/未收费账单/进行中的打印任务，若有则提示完成后再更新。

**R6 失败可回滚。** 更新失败必须能回到更新前状态：应用层面保留上一版本可回退；数据库层面依赖更新前备份恢复。

**R7 更新记录。** 每次更新写 `sys_migration`（数据库部分）与更新日志（应用部分），记录版本号、时间、结果、耗时。

**R8 不自动重启业务。** 更新完成后提示重启，**不在业务进行中自动重启进程**。

## 5. 验收标准

**AC1（更新前备份）**
- Given 存在可用更新
- When 点击更新
- Then 先生成一份完整备份且 `integrity_check` 通过，之后才开始下载；备份失败则中止更新并明确提示
- 验证方式：自动（mock 备份失败）

**AC2（校验和失败拒绝安装）**
- Given 下载到的更新包校验和与预期不符
- When 执行安装
- Then 拒绝安装，删除损坏包，记录 `E1006` 并告警，系统保持原版本可用
- 验证方式：自动（篡改包）

**AC3（离线降级）**
- Given 完全断网
- When 启动系统并检查更新
- Then 更新检查失败被静默处理，**系统正常启动且全部业务功能可用**，仅在状态区提示"无法检查更新"
- 验证方式：自动（断网）

**AC4（业务进行中禁止更新）**
- Given 存在一张未收费的账单
- When 触发更新
- Then 提示先完成或作废该账单，暂不执行更新
- 验证方式：自动

**AC5（迁移失败回滚）**
- Given 更新包含一条有错误的迁移脚本
- When 执行更新
- Then 迁移整体回滚，数据库版本不变，应用提示更新失败并保留可从备份恢复的入口
- 验证方式：自动（注入错误脚本）

**AC6（回滚可用）**
- Given 更新后系统异常
- When 执行回滚到上一版本
- Then 应用回到上一版本，数据库从更新前备份恢复，启动自检通过，业务数据为更新前状态
- 验证方式：自动

**AC7（更新日志完整）**
- Given 一次成功更新
- When 查看更新记录
- Then 含版本号、时间、结果、耗时、涉及迁移序号
- 验证方式：自动

## 6. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E1001 | 数据库不可用 | 是 |
| E1002 | 磁盘不足 | 是 |
| E1006 | 更新包校验失败 | 是（重新下载） |
| E1007 | 更新过程中业务未结束 | 是 |
| E5001 | 网络不可达（静默降级） | 是 |

---

## 7. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 下载中断 | 支持断点续传或重新下载；未完成的包不覆盖应用 |
| 安装中途崩溃 | 依靠更新前备份；启动时自检发现版本不一致 → 安全模式 + 引导恢复 |
| 迁移部分执行 | 迁移在事务内，整体回滚；不出现"一半新一半旧"的 schema |
