# M14 系统管理

> 阶段：第一阶段（第一个开发）
> 依赖：无（除 `03_GLOBAL_CONTRACTS` / `04_DATA_MODEL` / `05_RUNTIME_TOPOLOGY`）
> 被依赖：全部模块（登录会话、配置、用户角色、诊断能力是公共底座）

---

## 1. 模块职责

提供系统运行所需的基础设施：初始化、登录与锁屏、系统配置、用户与角色、日志与诊断、健康检查、版本更新、安全退出，以及基础数据包导入。

**本模块不承载任何业务单据。** 它只回答"谁在用、系统怎么配、系统是否健康、怎么安全地开始和结束"。

---

> `audit_login` 虽与登录相关，但归 **M12**（审计性质），本模块通过 M12 接口写入，不直接写表。

## 3. 模块级规则

**R-M14-1 配置来源唯一。** 所有可调参数（诊所名称、默认付数、代煎费、重试次数、备份路径、打印模板选择等）一律存 `sys_config`，禁止硬编码。读取走统一配置服务，带内存缓存与失效通知。

**R-M14-2 角色即权限边界。** 权限按角色授予（医生 / 药师 / 收费员 / 管理员）。单机单用户下允许一人兼多角色，但**登录时必须选定当前角色**，审计记录中的角色字段来源于此。切换角色视为一次独立会话事件，写 `audit_login`。

**R-M14-3 管理员不等于超级用户。** 管理员**无权修改已确认的病历内容**，也无权绕过处方确认流程。管理员仅拥有配置、用户管理、封存/解封（M11）、备份恢复（M13）权限。解封操作写 `audit_high_risk`。

**R-M14-4 锁屏是强制的。** 无操作超过配置阈值（默认 5 分钟）自动锁屏。锁屏期间不得有任何业务操作。解锁需重新验证密码，写 `audit_login`。

**R-M14-5 启动自检失败进安全模式。** 见 `05_RUNTIME_TOPOLOGY` §5.1。自检未通过时系统只读打开，禁止业务写入，仅允许管理员执行诊断与恢复。

**R-M14-6 编号服务全局唯一。** `sys_sequence` 是本系统唯一取号入口，任何模块不得自行生成编号。取号在事务内完成，允许跳号不允许重号。

**R-M14-7 数据字典驱动枚举。** 给药途径、煎法、脚注、单位、证型等枚举值一律存 `sys_dict`，不在代码中写死下拉项，便于诊所自行维护。

---

## 4. 状态机引用

本模块无业务单据状态机。会话状态：

```
sys_session: ACTIVE → LOCKED（超时/手动）→ ACTIVE（解锁）| LOGGED_OUT
```

## 5. 对外接口（供其他模块调用）

| 接口 | 说明 | 消费方 |
|---|---|---|
| `auth.currentUser()` | 当前用户 ID + 角色 | 全部（审计埋点必需） |
| `auth.require(permission)` | 权限校验，失败抛 `E6xxx` 并写 `audit_permission` | 全部 |
| `config.get(key)` / `config.set(key, value)` | 配置读写，set 写 `audit_high_risk` | 全部 |
| `seq.next(type, bizDate)` | 取号，**事务内调用** | 全部 |
| `dict.list(category)` | 数据字典枚举 | M03 / M06 / M07 / M08 |
| `log.write(level, module, message, context)` | 应用日志 | 全部 |
| `health.report(component, status, detail)` | 健康状态上报 | M10 / M13 |

## 7. 本模块的特殊约束

- **F128 必须做成最小版并提前可用**（至少支持药品、饮片、收费项目三类导入），否则 M06 / M07 / M09 无法测试。最小版随本模块第一阶段交付，完整版放第四阶段。
- 本模块的写操作（配置变更、用户角色变更、导入）全部写 `audit_high_risk`。
