# F103 系统日志

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: S]

---

## 1. 职责

应用运行日志的统一记录、分级、轮转与查看。**只用于运维排查，不用于合规追溯**（合规追溯归 M12 审计）。

---

## 2. 依赖

- 依赖：F101（日志级别与保留天数为配置项）
- 被依赖：全部模块

---

## 3. 涉及的表

`sys_diagnostic`（M14 自有，仅存关键诊断事件摘要）
主要输出为**文件**：`logs/app_{date}.log`、`logs/error_{date}.log`

---

## 4. 规则

**R1 日志 ≠ 审计。** 明确区分：

| | 日志（本功能） | 审计（M12） |
|---|---|---|
| 用途 | 运维排查 | 合规追溯 |
| 载体 | 文件 | 数据库 `audit_*` 表 |
| 可否删除 | 可轮转删除 | **禁止删除** |
| 内容 | 技术细节、堆栈、性能 | 谁在何时对什么业务做了什么 |

**禁止把审计信息只写进日志文件。** 所有业务操作必须同时写审计表。

**R2 分级。** DEBUG / INFO / WARN / ERROR / FATAL，级别由配置控制，默认 INFO。

**R3 结构化。** 每条日志含：时间（系统时间）、级别、模块名、功能点编号（如 `M06/F34`）、消息、异常码（若有）、上下文字段（单据 ID、用户 ID）。**不记录密码、身份证完整号等敏感原文**（身份证可记录后 4 位或哈希）。

**R4 轮转。** 按天切分，保留天数可配置（默认：app 30 天、error 90 天）。磁盘不足时优先删除最旧日志并告警，但**不得删除当天日志**。

**R5 异步写入。** 日志写入不得阻塞业务事务；进程崩溃前必须 flush（退出流程见 F107）。

**R6 ERROR 以上落库摘要。** ERROR / FATAL 级别同时写 `sys_diagnostic` 一行摘要（不含堆栈全文），便于界面查看与统计。

**R7 禁止日志作为唯一证据。** 关键业务结论（如"收费成功"）以数据库状态为准，日志仅作辅助。

---

## 5. 验收标准

**AC1（分级生效）**
- Given 日志级别配置为 WARN
- When 产生一条 INFO 与一条 ERROR 日志
- Then 文件中仅有 ERROR 那条，且 ERROR 同时写入 `sys_diagnostic`
- 验证方式：自动

**AC2（结构化字段）**
- Given 在 M06/F34 开处方时产生一条日志
- When 查看该条日志
- Then 包含时间戳、级别、模块名 M06、功能点 F34、消息、上下文（处方号、用户 ID）
- 验证方式：自动

**AC3（敏感信息脱敏）**
- Given 一次登录失败
- When 检查日志全文
- Then 不含明文密码；若记录身份信息则为脱敏形式
- 验证方式：自动（正则扫描）

**AC4（轮转与保留）**
- Given 保留天数配置为 7，存在 10 天前的日志文件
- When 触发清理
- Then 超过 7 天的日志被删除，7 天内与当天日志保留
- 验证方式：自动

**AC5（异步不阻塞）**
- Given 开启大量日志写入
- When 执行一笔收费事务
- Then 事务耗时不受日志写入影响（对比开关日志的耗时差 < 10%）
- 验证方式：自动（性能断言）

**AC6（崩溃前 flush）**
- Given 产生一批日志后立即强制 kill 进程
- When 重启检查日志文件
- Then kill 前 3 秒内产生的日志已落盘（不依赖缓冲区未刷新）
- 验证方式：自动

**AC7（审计不依赖日志）**
- Given 删除全部日志文件
- When 查询任意历史业务操作的审计记录
- Then 审计信息完整可读（来自数据库）
- 验证方式：自动

---

## 6. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E1002 | 磁盘满导致日志写入失败 | 是（清理后） |
| E2003 | 日志级别配置非法 | 否 |

---

## 7. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 日志文件不可写 | 降级：尝试写备用目录；仍失败则提升级别只写 ERROR 到内存并告警，不阻塞业务 |
| 磁盘满 | 触发清理最旧日志；仍不足则告警管理员 |
| `sys_diagnostic` 写失败 | 日志已落文件，诊断摘要允许丢失，不影响业务 |
