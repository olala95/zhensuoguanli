# F128 基础数据包导入

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: **L — 已拆分为 5 个子项，逐个子项独立验收**]

---

## 1. 职责

批量灌入系统运行所需的基础数据：药品目录、中药饮片目录、收费项目目录、ICD-10 诊断字典、处置项目目录。

**本功能是 M06 / M07 / M08 / M09 能否测试的前置条件。** 最小版必须随第一阶段交付。

---

## 2. 拆分

| 子项 | 内容 | 优先级 | 交付阶段 |
|---|---|---|---|
| **F128.1** 导入框架与模板 | 文件解析、字段映射、校验、预览、错误报告、回滚 | P0 | 第一阶段 |
| **F128.2** 药品与饮片目录导入 | `drug` + `herb` | P0 | 第一阶段（最小版） |
| **F128.3** 收费项目目录导入 | `charge_item` | P0 | 第一阶段（最小版） |

## 4. 涉及的表

`sys_import_job`（M14 自有）
**写入需授权**：`drug`/`herb`（M06 所有）、`charge_item`（M09 所有）、`treatment_item`（M08 所有）、诊断字典（M03 所有）

> **跨模块写入特例**：本功能需要写入其他模块的表。按 `00_AI_RULES` R2，必须通过对方模块的**导入接口**写入，不得直接 INSERT。各目标模块需提供 `import.upsert(rows)` 接口。

---

## 5. 规则

**R1 先校验后写入，全量事务。** 导入分两阶段：
- **校验阶段**：解析全部行，产出错误清单（行号、字段、原因），**不写任何数据**
- **写入阶段**：用户确认后才执行，整体在一个事务内，失败整体回滚

**R2 提供标准模板。** 系统内置 CSV/Excel 模板下载，含表头与示例行、字段说明。字段名同时支持中文表头与英文 key。

**R3 幂等（upsert）。** 以业务唯一键判定：`drug` 用批准文号+规格+厂家；`herb` 用饮片名称+炮制规格；`charge_item` 用项目编码。已存在则更新（可选择"跳过已存在"），不存在则新增。**重复导入不得产生重复数据**。

**R4 必填与格式校验。**

| 数据 | 必填字段 |
|---|---|
| 药品 | 通用名、剂型、规格、单位、批准文号、是否处方药 |
| 饮片 | 名称、炮制规格、单位(g)、常用量范围、是否毒性 |
| 收费项目 | 项目编码、名称、单价、单位、类别 |
| 诊断 | ICD-10 编码、名称 |
| 处置 | 项目编码、名称、单价、单位、类别 |

金额字段按契约 §3 存整数分；支持"元"输入自动转换。

**R5 错误可定位。** 错误报告精确到行号与列，支持导出错误清单，用户修正后可直接重新导入同一文件。

**R6 大文件分批处理。** 单次导入超过 2000 行时分批（每批 500 行）处理并显示进度；**整体仍在一个事务内**，失败整体回滚。

**R7 导入必审计。** 每次导入写 `audit_high_risk`：文件哈希、总行数、成功/失败/更新数、操作人、时间。导入内容明细不进审计（量大），但统计进审计。

**R8 导入中禁止业务操作。** 导入执行期间锁定相关表（`drug`/`herb`/`charge_item` 等），禁止同时开处方/收费，避免读到半导入状态。

**R9 不删除既有数据。** 导入只做新增与更新，**绝不因导入删除系统中已有的药品/项目**。若数据包标记为"已停用"，则置为停用状态而非删除。

## 6. 验收标准

### F128.1 导入框架

**AC1（校验阶段不写数据）**
- Given 一个含 10 行错误的导入文件
- When 执行导入到校验阶段
- Then 返回含 10 条错误（行号+字段+原因）的报告，数据库中**零变更**
- 验证方式：自动

**AC2（全量事务回滚）**
- Given 一个 1000 行文件，其中第 900 行有错但被强制提交
- When 执行写入
- Then 整体回滚，数据库回到导入前状态，错误报告指出第 900 行
- 验证方式：自动

**AC3（错误报告可定位可导出）**
- Given 导入失败
- When 导出错误清单
- Then 清单含行号、字段名、错误原因、原始值，用户按此修正后能重新导入
- 验证方式：自动

**AC4（进度与分批）**
- Given 5000 行文件
- When 执行导入
- Then 分批（每批 ≤500 行）执行并有进度显示，最终结果与一次性导入一致
- 验证方式：自动

### F128.2 药品与饮片

**AC5（药品导入成功）**
- Given 标准模板的药品文件 100 行
- When 导入
- Then `drug` 新增 100 条，必填字段完整，金额字段为整数分，可在 F33 药品搜索中查到
- 验证方式：自动

**AC6（饮片导入成功）**
- Given 标准模板的饮片文件 300 行（含毒性标记与最大剂量）
- When 导入
- Then `herb` 新增 300 条，毒性饮片 `is_toxic=1`，`max_dose_g` 正确；F111 开饮片处方可选到这些药
- 验证方式：自动

**AC7（幂等 upsert）**
- Given 已导入药品 A
- When 再次导入含药品 A 的同一文件，选择"更新已存在"
- Then `drug` 中药品 A 仍只有 1 条，字段被更新，总数不增加
- 验证方式：自动

**AC8（重复导入不产生脏数据）**
- Given 同一文件连续导入 3 次（跳过已存在模式）
- When 检查 `drug` 表
- Then 记录数与第 1 次导入后完全一致
- 验证方式：自动

### F128.3 收费项目

**AC9（收费项目可用）**
- Given 导入收费项目 200 条
- When 在 M09 中新增账单明细
- Then 可搜索并选择这些项目，单价正确（整数分）
- 验证方式：自动（跨模块，需 M09 配合）

### F128.4 诊断与处置

**AC10（诊断字典可用）**
- Given 导入 ICD-10 字典 5000 条
- When 在 F17 录入诊断
- Then 可按编码或名称拼音搜索到
- 验证方式：自动（跨模块，需 M03 配合，第四阶段）

### F128.5 数据包管理

**AC11（版本比对）**
- Given 系统已导入 v1.0 数据包，官方发布 v1.1
- When 检查更新
- Then 显示差异条目数与变更类型（新增/修改/停用），可选择增量导入
- 验证方式：自动（mock 数据包服务）

### 通用

**AC12（导入审计）**
- Given 一次成功导入
- When 查看 `audit_high_risk`
- Then 有一条记录含：文件哈希、总行数、新增数、更新数、失败数、操作人、时间
- 验证方式：自动

**AC13（导入中锁定）**
- Given 导入执行中
- When 尝试开处方
- Then 被拒绝或等待（明确提示"基础数据导入中"），**不会读到半导入状态的数据**
- 验证方式：自动

**AC14（不删除既有数据）**
- Given 系统中已有药品 X（数据包中不含 X）
- When 导入新数据包
- Then 药品 X 仍然存在且未被删除或停用（除非数据包显式标记为停用）
- 验证方式：自动

**AC15（崩溃恢复）**
- Given 导入执行到一半
- When 强制 kill 进程
- Then 重启后数据库无半导入数据（事务回滚），`sys_import_job` 状态标记为失败，可重新导入
- 验证方式：自动

## 7. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E2001 | 必填字段缺失 | 否（需修文件） |
| E2002 | 字段类型/格式错误 | 否 |
| E2004 | 业务唯一键冲突（跳过模式下为警告） | 否 |
| E2006 | 文件无法解析（编码/格式） | 否 |
| E2007 | 文件超过大小限制（>20MB） | 否 |
| E3010 | 导入中业务被锁定 | 是（等待） |

> **E3010 说明**：原草案写 E3004，但该码已被「皮试未做」（M06 F35）占用，故改用 E3010。

---

## 8. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 解析失败 | 不写入任何数据，提示文件问题 |
| 写入中途崩溃 | 事务整体回滚；`sys_import_job` 标记失败；重新导入即可 |
| 部分模块接口不可用 | 记录失败子项，其余子项继续；支持仅重试失败子项 |

---

## 9. 契约缺口

- **需各目标模块提供 `import.upsert(rows)` 接口**：M06（drug/herb）、M09（charge_item）、M08（treatment_item）、M03（诊断字典）。此接口契约需在第一阶段冻结，虽然 F128.4 要到第四阶段才实现。
