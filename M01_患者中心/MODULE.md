# M01 患者中心

> 阶段：第一阶段（第三阶段模块，紧随 M12）
> 依赖：M14（用户上下文、编号服务）、M12（审计接口）
> 被依赖：**M02 就诊**（必须有患者才能建 Visit）、M03 病历、M06 处方、M09 收费、M15 报表

---

## 1. 模块职责

患者主数据的建立、检索、维护与重复处理。患者是全部业务单据的根对象。

---

## 2. 表所有权（详见 `04_DATA_MODEL`）

| 表 | 职责 |
|---|---|
| `patient` | 患者主表（患者号、姓名、性别、出生日期、身份证等） |
| `patient_identifier` | 证件/卡号（身份证、其他标识卡） |
| `patient_contact` | 联系人与联系方式 |
| `patient_merge_log` | 重复患者合并记录 |

---

## 3. 模块级规则

**R-M01-1 患者号不可变。** 患者号 `P{yyyyMMdd}{4位}` 一经生成永久不变，合并时保留主患者号。

**R-M01-2 有业务数据的患者不可删除。** 存在有效 Visit / 处方 / 病历 / 账单的患者只能**合并或停用**，禁止删除（含软删除）。删除尝试写 `audit_high_risk`。

**R-M01-3 建档必填最小化。** 首次建档只要求：姓名、性别、出生日期（或年龄）、联系方式之一。其余可后补——**急诊/初诊场景不允许因字段不全而阻塞建档**。

**R-M01-4 身份证为强校验位。** 录入身份证时校验：18 位格式 + 校验位 + 出生日期与性别一致性。不一致给出提示但**允许强制保存**（标记 `id_verified=0`），因为现实中存在错号。

**R-M01-5 姓名不唯一。** 允许重名。重复判定依据：姓名 + 性别 + 出生日期，或身份证完全一致，或手机号一致。

**R-M01-6 合并不可逆。** 患者合并（F04）不可撤销。合并前必须展示将被影响的单据数量并二次确认，写 `audit_high_risk` 与 `patient_merge_log`。

**R-M01-7 联系方式可多值。** 一个患者可有多个电话/地址，`patient_contact` 支持多记录，其中一个标记为主要。

**R-M01-8 敏感信息保护。** 身份证在列表展示中默认脱敏（前 6 后 4 隐藏中间）；完整号码需要"查看"操作且该操作写 `audit_operation`。

**R-M01-9 年龄由出生日期推导。** 不存"年龄"字段（会过期），只存出生日期，展示时计算。出生日期未知时可存估计年份并标记 `birthdate_estimated=1`。

---

## 4. 状态机引用

本模块无状态机。`patient` 只有 `deleted_at` 软删除标记（受 R-M01-2 限制）。

---

## 5. 对外接口

| 接口 | 说明 | 消费方 |
|---|---|---|
| `patient.get(id)` | 按 ID 取患者 | 全部 |
| `patient.getByNo(no)` | 按患者号取 | M02 / M06 |
| `patient.search(criteria)` | 搜索（F02） | M02 / M06 / M09 |
| `patient.exists(criteria)` | 重复判定 | F01 |
| `patient.snapshot(id)` | 取不可变快照（姓名/性别/出生日期） | M06 处方、M09 账单、M11 归档 |

> **快照机制重要**：处方、账单、病历归档需保存患者信息的**当时快照**，不能只存外键——否则患者改名后历史单据信息跟着变，违反归档不可变原则。

## 7. 本模块的特殊约束

- **F01 建档是全流程第一步**，必须与 M02 的创建 Visit 无缝衔接（建档后可直接进入开就诊）。
- M03 在**第一阶段**开发时要冻结 AI 草稿接口；M01 需提供 `patient.snapshot()` 供后续模块使用，即使当时只有 M01 自己调用。
