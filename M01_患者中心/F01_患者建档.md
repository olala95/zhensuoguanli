# F01 患者建档

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: M]

---

## 1. 职责

创建新患者记录，分配患者号，录入基本信息与联系方式，并在建档时做重复提示。

---

## 2. 依赖

- 依赖：M14（`seq.next('PATIENT')` 取号、用户上下文）、M12（审计）、F02（重复判定复用搜索能力）、F73（身份证读取，M10 提供，可无）
- 被依赖：M02（建档后直接开就诊）

---

## 3. 涉及的表

`patient`、`patient_identifier`、`patient_contact`（M01 自有）

---

## 4. 规则

**R1 最小必填。** 必填：姓名、性别、出生日期（或年龄）、至少一个联系方式。其余（身份证、地址、过敏史标签、备注）可后补。**不允许因字段不全阻塞建档。**

**R2 患者号由编号服务生成。** `P{yyyyMMdd}{4位}`，事务内取号，允许跳号不允许重号。

**R3 身份证强校验但可强制保存。**

- 校验：18 位格式、校验位、出生日期与性别一致
- 校验不通过：提示具体原因，允许"仍然保存"，保存后 `id_verified=0`
- 身份证读取（F73）成功时自动填充并标记 `id_verified=1`

**R4 建档时重复提示。** 提交前用姓名+性别+出生日期 / 身份证 / 手机号 做重复检测：

- 命中 → 弹出候选列表（含患者号、姓名、年龄、最近就诊时间）
- 用户可选择"使用已有患者"或"仍然新建"
- 选择"仍然新建"需记录原因（写 `audit_operation` 上下文）

**R5 年龄与出生日期互推。** 输入年龄则反推估计出生年份并标记 `birthdate_estimated=1`；输入出生日期则显示年龄（含"月/天"精度用于儿科）。

**R6 联系方式多值。** 可录入多个电话/地址，标记一个为主要。电话格式做基本校验（位数），不做号段校验。

**R7 建档必审计。** 写 `audit_operation`（create）+ 关键字段的 `audit_data_change`。身份证字段审计中只记后 4 位 + 哈希。

**R8 建档后可直接开就诊。** 提供"保存并开就诊"按钮，一步进入 M02 的 F05。

**R9 手工建档与硬件建档同源。** 身份证读取只是填充手段，最终走同一保存逻辑与校验规则。

---

## 5. 状态与流程

```
进入建档
  → 可选：刷身份证（F73）自动填充
  → 录入必填项
  → 提交时重复检测
      → 命中：展示候选 → 选已有 / 仍然新建（记原因）
      → 未命中：直接保存
  → 取患者号（事务内）
  → 写入 patient / patient_identifier / patient_contact（同一事务）
  → 写审计（同一事务）
  → 可选：直接进入创建 Visit
```

---

## 6. 验收标准

**AC1（最小建档成功）**

- Given 录入姓名"张三"、性别男、出生日期 1990-01-01、手机号 13800000000
- When 提交建档
- Then 生成患者号 `P{今日}{4位}`，患者记录落库，手机号写入 `patient_contact` 并标记主要，审计记录完整
- 验证方式：自动

**AC2（必填校验）**

- Given 未填姓名
- When 提交
- Then 拒绝并返回 `E2001`，提示缺失字段，不生成患者号（不消耗序列）
- 验证方式：自动

**AC3（身份证校验失败可强制保存）**

- Given 输入身份证 11010119900101123X（校验位错误）
- When 提示后选择"仍然保存"
- Then 保存成功，`id_verified=0`，审计中不出现完整身份证号
- 验证方式：自动

**AC4（身份证读取填充）**

- Given 身份证读卡器可用
- When 刷卡
- Then 姓名、性别、出生日期、身份证号、地址自动填充，`id_verified=1`
- 验证方式：自动（mock 读卡器）

**AC5（读卡器不可用降级）**

- Given 身份证读卡器不可用
- When 进入建档
- Then 可完全手工录入，**不阻塞建档**，界面提示读卡器不可用
- 验证方式：自动（mock 失败）

**AC6（重复提示）**

- Given 系统已有"张三 / 男 / 1990-01-01"
- When 再次录入相同信息提交
- Then 弹出候选列表，显示患者号与最近就诊时间；可选择使用已有患者
- 验证方式：自动

**AC7（仍然新建留痕）**

- Given 重复提示出现
- When 用户选择"仍然新建"并填写原因"确为不同人"
- Then 创建新患者，`audit_operation` 上下文含重复提示已出现与用户填写的原因
- 验证方式：自动

**AC8（患者号唯一）**

- Given 连续建档 10 名患者
- When 检查患者号
- Then 10 个号全部唯一且格式正确；强制 kill 后重开不产生重复号
- 验证方式：自动

**AC9（建档后直接开就诊）**

- Given 刚建档完成
- When 点击"保存并开就诊"
- Then 携带该患者进入 M02 创建 Visit 界面
- 验证方式：自动（跨模块，需 M02 配合）

**AC10（崩溃一致性）**

- Given 建档提交过程中强杀进程
- When 重启检查
- Then 患者记录要么完整存在（含联系人、审计）要么完全不存在，无半条记录
- 验证方式：自动

## 7. 异常码

| 码     | 场景            | 可重试 |
| ----- | ------------- | --- |
| E2001 | 必填字段缺失        | 否   |
| E2002 | 字段格式错误（电话/日期） | 否   |
| E2008 | 身份证校验位错误（可强制） | 否   |
| E2004 | 身份证重复（提示已有患者） | 否   |
| E4001 | 身份证读卡器不可用（降级） | 是   |
| E1010 | 审计写入失败        | 是   |

---

## 8. 失败恢复

| 失败点      | 恢复方式                              |
| -------- | --------------------------------- |
| 保存中途崩溃   | 事务回滚，无半条患者；重新建档                   |
| 取号失败     | 事务回滚；序列不消耗或允许跳号                   |
| 读卡器失败    | 降级手工录入（AC5）                       |
| 重复检测服务异常 | 允许跳过检测直接建档，并标记"未做重复检测"便于后续 F04 处理 |
