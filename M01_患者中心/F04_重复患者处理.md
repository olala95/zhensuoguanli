# F04 重复患者处理

[TYPE: FEATURE] [PRIORITY: P0] [SIZE: **L — 已拆分为 4 个子项**]

---

## 1. 职责

识别系统中的重复患者，并将其合并为一条主记录，同时保证历史业务数据不丢失、不指向错误患者。

**这是本模块风险最高的功能**：合并不可逆，且涉及把 A 名下的所有单据改挂到 B 名下。

---

## 2. 拆分

| 子项 | 内容 | 优先级 |
|---|---|---|
| **F04.1** 重复检测 | 按规则扫描疑似重复，产出候选对 | P0 |
| **F04.2** 合并预览与确认 | 展示将被影响的单据清单，二次确认 | P0 |
| **F04.3** 合并执行 | 事务内改挂全部单据，保留主患者号 | P0 |
| **F04.4** 合并回滚与日志 | 完整日志，支持"反向提示" | P0 |

---

## 3. 依赖

- 依赖：M12（`audit_high_risk`）、M14（用户上下文）
- 被依赖：无（运维功能）

## 4. 涉及的表

`patient`、`patient_merge_log`（M01 自有）
**改挂其他模块的表**（`visit`、`prescription`、`bill` 等）必须通过对方模块提供的接口，**禁止直接 UPDATE**（`00_AI_RULES` R2）

## 5. 规则

**R1 重复判定规则（F04.1）**

| 等级 | 判定条件 | 处理 |
|---|---|---|
| 高 | 身份证完全一致 | 强提示，建议合并 |
| 高 | 姓名 + 性别 + 出生日期 完全一致 | 强提示 |
| 中 | 姓名 + 手机号一致 | 提示 |
| 中 | 姓名相同 + 出生日期相差 ≤1 年（录入误差） | 提示 |
| 低 | 姓名相同 + 年龄接近 | 列表展示，不主动提示 |

**R2 绝不自动合并。** 系统只提供候选与建议，**任何合并都必须人工确认**。自动合并会在诊所场景下造成严重医疗事故风险。

**R3 合并必须预览（F04.2）。** 执行前展示：
- 主患者与次患者的完整对比（分字段并排）
- 将被改挂的单据数量与类型明细（就诊 N 条、处方 M 张、账单 K 笔…）
- 冲突字段的处理结果（哪个值会保留）
- 明确提示"不可逆"

**R4 合并字段保留规则（F04.3）**

| 字段 | 规则 |
|---|---|
| 患者号 | **保留主患者号**，次患者号归档进 `patient_merge_log` |
| 姓名 | 保留主患者；若次患者有身份证且主患者无，提示人工确认 |
| 出生日期/性别 | 保留主患者；不一致时**强制人工确认** |
| 身份证 | 主患者无则取次患者；都有且不同 → **禁止合并**，需人工处理 |
| 联系方式 | **并集保留**，不丢弃次患者的联系方式 |
| 备注/标签 | 合并（拼接），不覆盖 |

**R5 单据改挂在事务内。** 全部单据改挂 + 次患者软删除 + 日志写入 + 审计写入，**必须在同一事务**，任一失败整体回滚。

**R6 改挂走接口不直接写表。** 各模块需提供 `patient.reassign(fromId, toId)` 接口；M01 调用它完成改挂。

**R7 已归档病历特殊处理。** 已归档（M11）的病历**不改挂**，因为归档文档具有法律效力且已固化患者快照。合并时明确提示"N 份已归档病历将保留在原患者名下"。

**R8 合并不可逆但可追溯（F04.4）。** `patient_merge_log` 完整记录：主次患者 ID 与患者号、合并前双方完整数据快照、被改挂单据清单（类型+ID）、操作人、时间、原因。

**R9 次患者不可再用于新业务。** 合并后次患者标记 `merged`，F02 可搜到但不可建就诊（配合 F02 AC8）。

**R10 身份证冲突禁止合并。** 双方身份证都存在且不同 → 系统拒绝合并，提示"疑似不同人，请人工核实"。这是防止最严重医疗差错的硬规则。

## 6. 验收标准

### F04.1 重复检测

**AC1（身份证一致检出）**
- Given 两名患者身份证完全相同
- When 执行重复检测
- Then 该对被列为"高置信度"候选
- 验证方式：自动

**AC2（姓名+性别+出生日期一致检出）**
- Given 两名患者姓名、性别、出生日期均相同但无身份证
- When 执行检测
- Then 列入候选
- 验证方式：自动

**AC3（不误报）**
- Given 两名患者仅姓名相同，性别与年龄均不同
- When 执行检测
- Then 不列入高置信度候选（最多低置信度展示）
- 验证方式：自动

### F04.2 预览与确认

**AC4（预览完整）**
- Given 次患者名下 3 次就诊、5 张处方、2 笔账单
- When 进入合并预览
- Then 明确列出"就诊 3、处方 5、账单 2"及各自的单号，并标注不可逆
- 验证方式：自动

**AC5（字段冲突人工确认）**
- Given 主次患者性别不同
- When 进入合并预览
- Then 强制要求人工选择保留哪个，不允许直接执行
- 验证方式：自动

**AC6（身份证冲突禁止合并）**
- Given 双方身份证均存在且不同
- When 尝试合并
- Then 系统拒绝并提示"疑似不同人，请人工核实"
- 验证方式：自动

### F04.3 合并执行

**AC7（单据全部改挂）**
- Given 确认合并
- When 执行
- Then 次患者名下全部未归档单据改挂到主患者，主患者号保留，次患者标记 merged
- 验证方式：自动

**AC8（联系方式并集）**
- Given 主患者有电话 A，次患者有电话 B
- When 合并
- Then 主患者同时拥有 A 和 B，不丢 B
- 验证方式：自动

**AC9（已归档病历不改挂）**
- Given 次患者有 2 份已归档病历
- When 合并
- Then 这 2 份仍保留在次患者名下，预览中已明确提示
- 验证方式：自动（跨模块，需 M11 配合）

**AC10（事务性）**
- Given 合并过程中某一单据改挂失败
- When 执行
- Then 整体回滚，主次患者均回到合并前状态，无半成品
- 验证方式：自动（注入失败）

**AC11（不直接写别的表）**
- Given 合并执行
- When 检查调用链
- Then 全部改挂通过对方 `patient.reassign()` 接口完成，无直接 UPDATE 他模块表
- 验证方式：自动（代码/调用审计）

### F04.4 日志与追溯

**AC12（日志完整）**
- Given 一次合并完成
- When 查看 `patient_merge_log`
- Then 含主次患者 ID 与患者号、合并前双方完整快照、被改挂单据清单、操作人、时间、原因
- 验证方式：自动

**AC13（高风险审计）**
- Given 一次合并完成
- When 查看 `audit_high_risk`
- Then 含合并记录，原因必填，操作人与时间完整
- 验证方式：自动

**AC14（合并后次患者不可用）**
- Given 合并完成
- When 用次患者创建就诊
- Then 被拒绝并提示已合并至主患者
- 验证方式：自动

**AC15（历史可追溯）**
- Given 合并后
- When 搜索次患者号
- Then 仍可找到次患者记录，显示"已合并至 Pxxx"，可查看其保留的已归档病历
- 验证方式：自动

## 7. 异常码

| 码 | 场景 | 可重试 |
|---|---|---|
| E2001 | 合并原因必填缺失 | 否 |
| E3009 | 双方身份证冲突，禁止合并 | 否 |
| E3010 | 字段冲突需人工确认 | 否 |
| E3011 | 改挂失败（事务回滚） | 是 |
| E1010 | 审计写入失败 | 是 |

---

## 8. 失败恢复

| 失败点 | 恢复方式 |
|---|---|
| 合并执行中途崩溃 | 事务回滚，**绝不出现部分改挂**；重启后可重新执行 |
| 部分单据接口不可用 | 整体回滚并提示哪个模块不可用 |
| 合并后发现问题 | **不支持自动撤销**；提供完整日志供人工核对；如需回退只能通过备份恢复（`audit_high_risk` 记录） |

---

## 9. 契约缺口

- **需各业务模块提供 `patient.reassign(fromId, toId)` 接口**：M02（visit）、M06（prescription）、M09（bill）、M05（lab_order）、M08（treatment_execution）。接口需定义"哪些状态允许改挂""已归档如何处理"。此契约需在第一阶段冻结（M02/M03 开发时）。
